## 결정과 이유

### 리전은 기본값(미국 동부 `iad1`) 그대로 재 보기

- 목표가 "해외 서버에서 서울시 API가 불리는지"라서 기본값으로 쟀다. 서울(`icn1`)로 옮기는 건 결과를 보고 정한다. 미국 값을 먼저 재 두면 11/9 이후 "미국 → 서울 전후 비교"로 쓸 수 있다.
- 빌드도 `iad1`에서 돌고 빌드 때 `/api/places`를 미리 만들면서 121곳을 부르므로, **빌드 로그가 첫 해외 호출 테스트**가 됐다. `SEOUL_API_KEY`가 없으면 121곳이 모두 실패해 빌드가 실패하므로 환경변수를 첫 배포 전에 넣었다.

### 호출 시간은 브라우저가 아니라 서버 로그로 잰다

- `cacheLife`의 `revalidate`는 시간이 지나도 **옛 결과를 바로 주고 뒤에서 다시 부른다**(Next 문서 `cacheLife.md`: "the next request will trigger a background refresh"). 그래서 `curl`로 재면 항상 캐시된 빠른 값만 나오고, 121곳 호출 시간은 보이지 않는다.
- 그래서 `getPlaces` 안에서 `performance.now()`로 `Promise.allSettled` 앞뒤를 재서 `console.log` 한 줄로 남겼다: `121곳 호출 1023ms, 성공: 121 실패: 0`.
- `'use cache'` 함수 본문은 캐시가 없을 때만 실행되므로 **로그 한 줄 = 실제 121곳 호출 한 번**이다. 줄 수로 하루 호출 수를, 실패가 있는 줄로 실패율을 구할 수 있다. 전에는 실패할 때만 로그가 있어서 전체 호출 수(분모)가 없었다.
- `Date.now()`는 Cache Components에서 막는 값이지만 `performance.now()`는 측정용이라 막지 않는다(Next 문서 `08-caching.md`).
- 서버 `console.log`는 Vercel Logs에만 남고 방문자 브라우저 Console에는 나오지 않는다. 키가 든 `url`은 찍지 않는다.

### `expire` 10분은 그대로

- 로그가 재는 건 "121곳 부르는 데 걸리는 시간"이고 `expire` 값과 상관없다. `expire`는 10분 넘게 아무도 안 왔을 때 다음 사람이 그 시간만큼 기다리게 할지만 정한다.
- 미국에서 약 1초라 기다릴 만하다고 보고 그대로 둔다. 로그가 쌓이면 다시 본다(3초 이상이면 검토).

### shadcn을 토큰보다 먼저 설치

- `tokens.md`는 `shadcn init`이 만든 `:root`·`@theme inline`이 있다는 전제로 쓰여 있었는데, 실제로는 아직 설치 전이었다. 그대로 붙이면 ★ 변수(`bg-background` 등)의 클래스 연결이 없어서 동작하지 않는다.
- 나중에 init하면 토큰을 넣은 `globals.css`에 shadcn 색을 덮어써서 다시 정리해야 하므로 먼저 설치했다.
- 부품 라이브러리는 **Radix**: `02` 문서 결정과 같고, 모바일 바텀시트에 쓸 Drawer(`vaul`)가 Radix 기반이고, 자료가 가장 많다.
- preset은 기본값 **Nova**(Lucide 아이콘 / Geist 글꼴). 색은 토큰으로 덮고 글꼴은 Pretendard로 바꾸므로 어느 preset이든 결과 차이가 작다.

### 토큰 정리 방식

- ★ 변수는 이름은 그대로, 값만 primitive로 바꿨다. `:root`는 `tokens.md` 분류대로 `/* 바탕과 면 */`, `/* 글자 */`, `/* 테두리 */`, `/* 상태 */`, `/* 혼잡도 */`, `/* 지도 */`, `/* 모양 */` 주석을 달고 순서를 맞췄다.
- 문서에 없는 shadcn 변수(`--secondary`, `--popover-foreground`, `--chart-*`, `--sidebar-*` 등)는 `/* shadcn 기본값 (tokens.md에 없음) */` 아래에 모아 그대로 뒀다. `.dark`도 쓰지 않지만 그대로 둔다.
- `@theme inline`에 우리 semantic 37줄(`--color-…`)을 추가했다.

### 모서리: `--radius` 하나로는 2 / 4 / 6px를 못 만든다

- 새 shadcn은 `sm = radius × 0.6`, `md = × 0.8`, `lg = × 1`로 **곱해서** 나눈다(예전 shadcn은 6−4, 6−2, 6으로 뺐다). 우리 디자인 비율은 2 : 4 : 6 = 0.33 : 0.67 : 1이라 어떤 값을 넣어도 셋이 동시에 맞지 않는다(sm=2px면 r≈3.33, md=4px면 r=5, lg=6px면 r=6).
- `--radius: 6px`에 `--radius-sm: 2px`, `--radius-md: 4px`를 고정값으로 넣었다. 배수를 1/3, 2/3으로 바꾸는 방법도 있지만, 디자인 값이 정해져 있어 바로 읽히는 쪽을 골랐다.
- shadcn `button.tsx`는 `rounded-lg`(6px)를 쓴다. 디자인의 버튼은 2px라 실제로 쓸 때 고친다.

### Pretendard는 dynamic subset (`next/font/local` 아님)

- 한글 글꼴 전체 파일은 약 2MB다(직접 재지는 않음). `next/font/local`은 그 한 덩어리를 첫 화면에서 미리 받는다(`preload` 기본값).
- dynamic subset은 92조각으로 나뉘어 있고 각 `@font-face`의 `unicode-range`에 맞는 글자가 화면에 있을 때만 그 조각을 받는다. 우리 화면은 글자가 적어서(구 이름, 제목, 범례) 받는 양이 확 준다.
- 대신 `next/font`의 자동 기능(대체 글꼴 크기 보정으로 글꼴이 바뀔 때 덜 흔들리게)은 못 쓴다. 이 보정은 Arial 기준이라 한글에는 효과가 적을 것으로 추측한다.
- 11/9 이후 Lighthouse로 두 방식의 LCP·CLS를 비교해 볼 수 있다.

> 면접용: "Pretendard를 `next/font`로 쓰면 2MB 파일 전체를 첫 화면에서 미리 받습니다. 지도 위주라 화면에 글자가 적어서 대부분이 낭비이고, 그동안 지도 데이터나 JS와 네트워크를 나눠 씁니다. 그래서 필요한 글자 조각만 받는 dynamic subset을 썼고, 첫 화면에서 92조각 중 3조각(약 85kB)만 받는 것을 확인했습니다."

### 구 평균: 서울대공원은 따로 처리하지 않아도 빠진다

- 규칙(03 문서): 구 대표값 = 장소 단계 평균(여유 1 ~ 붐빔 4), 반올림. 서울대공원은 구 평균에서 뺀다.
- 서울대공원의 `guName`은 `'과천시'`라서 구별로 묶으면 혼자 `과천시` 묶음이 된다. 서울 어느 구 평균에도 안 섞이고, 과천 자리 색은 그 묶음 값(= 서울대공원 단계)을 쓰면 된다.
- 장소가 없는 구(중랑구, 또는 오늘 장소가 다 실패한 구)는 묶음에 칸이 안 생긴다. 그래서 `0 ÷ 0 = NaN`이 생기지 않고, 결과에서 `undefined`이면 화면에서 "데이터 없음(회색)"으로 처리한다.
- `Math.round`는 `.5`를 올린다(2.5 → 3). 딱 중간이면 더 붐비는 쪽으로 보인다. 사람 적은 곳을 찾는 서비스라 붐빔을 덜 보여 주는 것보다 안전하다고 봤다.

### `congestion.ts`를 함수 넷으로 나누고 export는 쓸 곳만

- `levelToScore` / `scoreToLevel`은 `place.ts`의 `CONGEST_LEVELS` 순서(위치 + 1 = 점수)를 써서 단계 목록을 한 곳에서만 관리한다.
- `groupByGu`를 따로 둔 이유: 평균 전에 묶기만 따로 확인할 수 있고(121곳 전부, 중랑구 없음을 먼저 확인), 구 클릭 시 장소 목록에도 다시 쓴다.
- `getGuLevels(places)`가 안에서 `groupByGu`를 불러서, 쓰는 쪽은 한 번만 부르면 된다.
- `scoreToLevel`은 파일 안에서만 쓰므로 export하지 않았다. `levelToScore`는 나중에 정렬(혼잡도 높은 순)에 쓸 거라 export.

## 문제와 해결

### 호출 시간이 0에 가깝게 찍힘

- **원인**: `const start = performance.now()`를 `Promise.allSettled`가 **끝난 뒤**에 둬서, 아무것도 안 하는 시간을 쟀다.
- **해결**: `start`를 `Promise.allSettled` 바로 위로 옮겼다. 로컬 537ms가 나왔다.

### 같은 로그가 두 번 찍힘 (`Cache` 접두어)

- 121곳을 두 번 부른 게 아니다. 개발 서버에서는 캐시 함수 안의 로그를 `Cache` 접두어를 붙여 한 번 더 보여 준다(Next 문서 `use-cache.md` "Console log replays"). 숫자가 같은 것이 같은 실행이라는 증거다.

### 장소코드 없는 실패: `Cannot read properties of undefined (reading 'AREA_CD')`

- **관찰**: 로컬 빌드 중 121곳 중 2곳이 이 오류로 실패했다. 우리가 만든 오류가 아니라서 장소코드가 없었다.
- **원인 추정**: `reading '0'`이 아니라 `reading 'AREA_CD'`이므로 장소 배열은 있는데 **비어 있었다**(`INFO-000`인데 `[]`). TypeScript는 기본 설정에서 배열의 `[0]`을 항상 값이 있다고 봐서 미리 잡지 못했다. 실제 응답은 아직 확인하지 못했다.
- **해결**: `fetch-place.ts`에서 `[0]`을 꺼낸 뒤 비어 있으면 `` `${code} 서울시 API 오류: 장소 데이터 없음 (빈 배열)` ``로 throw. 로그가 쌓이면 같은 장소가 반복되는지(그 장소 문제) 그때그때 다른지(서버 일시 문제) 구분해서 대응을 정한다.
- `adapter.ts`의 `올바르지 않은 혼잡도 레벨` 오류에도 장소코드가 없다. 실제로 일어나면 고친다.

### `scoreToLevel` 범위 검사 빈틈

- `score >= 5 || score <= 0`만 쓰면 `2.5`와 `NaN`이 통과해 `undefined`를 돌려준다. `NaN`은 어떤 비교를 해도 `false`라서다.
- `Number.isInteger`만 쓰면 이번엔 `0`, `5`가 통과한다.
- 둘을 `||`로 같이 써서 1·2·3·4만 통과하게 했다. `0 5 -1 2.5 NaN` 모두 throw, 네 단계 왕복 변환 확인.

### Geist를 빼고 나서 글꼴이 사라짐

- shadcn이 `@theme inline`에 `--font-sans: var(--font-sans);`를 넣어 두고, 값은 `layout.tsx`의 Geist가 `<html>`에 넣어 줬다. Geist를 빼자 자기 자신을 가리키는 값이 됐다.
- `tokens.md` 값(`'Pretendard Variable', Pretendard, system-ui, sans-serif`)으로 바꿨다.

### Geist를 지웠는데 Network에 `geist-latin.woff2`가 보임

- `node_modules/next/dist/next-devtools/server/font/geist-latin.woff2`. **Next 개발 도구(왼쪽 아래 N 버튼)가 쓰는 글꼴**이다. 개시자가 `(색인)`이 아니라 `기타`였고, 우리 HTML에는 Geist `<link>`가 없었다. `pnpm dev`에서만 나온다.
- 처음 보였을 때는 HMR로 옛 HTML이 남아 있었고 "로그 보관"도 켜져 있었다.

### 로컬 빌드에서 `ENOTFOUND` (`POI098`)

- 내 컴퓨터가 `openapi.seoul.go.kr`의 IP를 찾지 못했다(DNS). 로컬 네트워크 문제로 보이고 1곳만 빠졌다. 장소코드가 찍혀서 `AREA_CD` 오류와 대비됐다.

## 확인한 사실

- 미국 동부(`iad1`) 서버에서도 서울시 API(`http://openapi.seoul.go.kr:8088`) 121곳이 모두 불렸다.
- Vercel 빌드에서도 `/api/places`는 Static(○)으로 미리 만들어지고 Revalidate 5m / Expire 10m가 그대로다.
- Vercel 대시보드 로그는 종류가 나뉜다: CDN 요청 로그(`cdn-requests`, 파일 요청만), Build Logs(빌드 때 출력), Logs(함수 실행 중 출력).
- `cn` 패키지는 shadcn 공식 저장소(`shadcn-ui/cn`)에서 만든 것으로 `clsx` + `tailwind-merge`를 합친 것이다. `src/lib/utils.ts`는 이를 다시 내보내고, `button.tsx`는 `cn`에서 바로 가져온다.
- shadcn 기본 `--radius`는 `0.625rem`(10px): sm 6 / md 8 / lg 10 / xl 14px.
- 프로젝트의 `*.css` 전부를 `@tailwindcss/turbopack`으로 보내는 설정에서도 Pretendard 패키지 CSS가 정상 처리됐다. 빌드 결과에 `@font-face` 92개, `woff2` 92개가 `.next/static/media/`로 복사됐다.
- 내 컴퓨터에 Pretendard가 설치돼 있어서 눈으로는 적용 여부를 구별할 수 없다. Elements → 계산됨 → 렌더링된 글꼴이 "네트워크 리소스"인지로 확인했다.
- 실제 `/api/places`로 `getGuLevels` 결과: 구 25개(서울 24 + 과천), 중구·종로·마포 '보통', 과천 '여유'. 손 계산과 같았다.

## 새로 배운 것

### `performance.now()`

- 페이지(브라우저) 또는 프로세스(서버)가 시작된 뒤 지난 시간을 ms 단위 소수로 돌려준다.
- 작업 앞에서 한 번, 뒤에서 한 번 불러 빼면 그 작업에 걸린 시간이다. `start`는 반드시 재려는 작업 **앞에** 둬야 한다(오늘 뒤에 둬서 0ms가 찍혔다).
  ```ts
  const start = performance.now();
  const results = await Promise.allSettled(/* 121곳 */);
  const ms = Math.round(performance.now() - start);
  ```
- Cache Components는 `Date.now()`처럼 실행할 때마다 값이 달라지는 함수를 막지만, `performance.now()`는 측정용이라 막지 않는다.

### `console.log`는 코드가 실행된 곳에 찍힌다

- 서버에서 실행되는 코드(`getPlaces`처럼 `server-only`)의 로그는 로컬에서는 `pnpm dev`를 켠 터미널, 배포 환경에서는 Vercel 대시보드의 Logs에 남는다. 볼 수 있는 사람은 프로젝트 주인뿐이다.
- 브라우저에서 실행되는 코드(클라이언트 컴포넌트)의 로그만 방문자의 개발자도구 Console에 나온다.
- 그래서 서버 로그에 측정값을 남겨도 방문자에게 보이지 않는다. 대신 서버 로그도 대시보드에 저장되므로 인증키가 들어간 `url`은 찍지 않는다.

### headless 부품 라이브러리

- 드롭다운·대화상자 같은 부품의 **동작**(열고 닫기, 화살표 키 이동, ESC로 닫기, 바깥 클릭, 스크린리더용 `aria-*`)만 만들어 주고, 색·크기 같은 **모양**은 비워 둔 라이브러리다. Radix(WorkOS), Base UI(MUI 팀), React Aria(Adobe)가 있다.
- shadcn은 이 동작 위에 Tailwind로 모양을 입힌 코드를 프로젝트 안에 복사해 준다. 그래서 shadcn 설치 때 고르는 "component library"는 "부품 안쪽 동작을 누가 만든 것으로 쓸까"라는 선택이다.

### `@theme inline`

- Tailwind v4에서 CSS 변수를 클래스 이름과 연결하는 곳이다. `--color-이름: 값`을 적으면 `bg-이름`, `text-이름`, `fill-이름`, `stroke-이름`, `border-이름` 같은 색 클래스가 한꺼번에 생긴다. 같은 원리로 `--radius-이름`은 `rounded-이름`, `--font-이름`은 `font-이름`이 된다.
- 층으로 보면 이렇다. 색을 정하는 건 `:root`이고, `@theme inline`은 연결만 한다. 그래서 색을 바꿀 때는 `:root`의 semantic 값만 고친다.
  ```
  1층 primitive  :root          --red-200: #ee9a7e
  2층 semantic   :root          --congestion-busy: var(--red-200)
  연결           @theme inline  --color-congestion-busy: var(--congestion-busy)
                                → bg-/fill-/stroke-congestion-busy 클래스
  ```
- `inline`은 만들어진 클래스 안에 `:root` 변수를 **바로** 쓰라는 뜻이다. 빌드 결과가 `.bg-congestion-busy{background-color:var(--congestion-busy)}`처럼 `--color-…`를 거치지 않는다.

### `calc`로 크기를 묶는 이유

- shadcn은 `--radius-sm: calc(var(--radius) * 0.6)`처럼 크기들을 `--radius` 하나에서 계산한다. `--radius` 하나만 바꾸면 모든 모서리 크기가 같은 비율로 바뀌게 하려는 것이다(여러 사람이 각자 디자인에 맞춰 쓰는 도구라서).
- 화면 너비나 브라우저 차이와는 관계없다. `calc` 안에 `vw`나 미디어 쿼리가 없어서 화면 크기가 바뀌어도 값은 그대로다.
- 단, shadcn 기본값 `0.625rem`의 `rem`은 사용자가 브라우저 글자 크기를 키우면 같이 커지는 단위다(기본 16px 기준 10px).

### `next/font`의 자동 최적화

`next/font`(Next에 들어 있는 글꼴 도구)로 글꼴을 불러오면 Next가 세 가지를 해 준다(Next 문서 `font.md`).

- **미리 받기(`preload`, 기본 켜짐)**: HTML에 `<link rel="preload">`를 넣어서, 브라우저가 CSS를 다 읽기 전부터 글꼴 파일을 받기 시작하게 한다. 파일이 크면(Pretendard 전체 약 2MB) 첫 화면에 필요한 다른 파일과 네트워크를 나눠 쓰게 돼서 오히려 불리하다.
- **`display: 'swap'`(기본값)**: 아래 "FCP"에서 설명.
- **대체 글꼴 크기 보정(`adjustFontFallback`)**: 글꼴이 오기 전에 보여 주는 대체 글꼴(로컬 글꼴은 기본 Arial)의 크기를 진짜 글꼴과 비슷하게 맞춰서, 글꼴이 바뀌는 순간 줄 길이가 달라져 화면이 밀리는 것(CLS, Cumulative Layout Shift)을 줄인다. Arial에는 한글이 없어서 한글에는 효과가 적을 것으로 추측한다.

### dynamic subset

- 한글은 완성형만 11,172자라 글꼴 파일이 크다. Pretendard dynamic subset은 이 파일을 92조각으로 나누고, 조각마다 `@font-face`를 하나씩 둔다.
- 각 `@font-face`에는 그 조각이 맡은 글자 범위(`unicode-range`)가 적혀 있다. 브라우저는 **화면에 실제로 나온 글자가 속한 조각만** 받는다.
  ```css
  @font-face {
    font-family: 'Pretendard Variable';
    font-display: swap;
    src: url(./woff2-dynamic-subset/PretendardVariable.subset.0.woff2)
      format('woff2-variations');
    unicode-range: U+f9ca-fa0b, U+ff03-ff05, ...;
  }
  ```
- 오늘 "내향인 지도" 다섯 글자만 있는 화면에서는 92조각 중 3조각(84.5kB)만 받았다.

### FCP와 `font-display: swap`

- **FCP(First Contentful Paint)**: 페이지를 열고 화면에 처음으로 글자나 그림 같은 내용이 그려지는 순간. 성능 지표 중 하나다.
- **`font-display`**: 웹 글꼴 파일이 아직 도착하지 않았을 때 글자를 어떻게 보여 줄지 정하는 `@font-face` 속성이다.
  - `block`: 글꼴이 올 때까지(최대 약 3초) 글자를 **투명하게** 숨긴다. 글자가 FCP 후보라면 그만큼 늦어질 수 있다.
  - `swap`: 글꼴을 기다리지 않고 **시스템 글꼴로 먼저 그리고**, 글꼴이 도착하면 그 글꼴로 **바꿔 끼운다(swap)**.
- `next/font`의 기본값도, Pretendard dynamic subset CSS의 값도 `swap`이다. 그래서 글꼴 파일이 크더라도 글자가 처음 그려지는 순간(FCP)은 글꼴 다운로드 때문에 늦어지지 않는다. 글꼴 크기가 문제가 되는 건 FCP보다는 받는 양 낭비와 다른 파일과의 네트워크 경쟁이다.
- 대신 `swap`은 시스템 글꼴 → Pretendard로 바뀌는 순간 글자 폭이 달라져 화면이 살짝 밀릴 수 있다(CLS). `next/font`의 크기 보정이 이걸 줄이려는 기능이다.

### `NaN`

- "Not a Number". 숫자 계산이 의미 없을 때 나오는 값이다. 예: `0 / 0`, `Number('abc')`.
- **어떤 비교를 해도 `false`**다. `NaN >= 5`도, `NaN <= 0`도, 심지어 `NaN === NaN`도 `false`다. 그래서 `score >= 5 || score <= 0` 같은 범위 검사를 그대로 통과해 버린다.
- `Number.isInteger(값)`은 정수일 때만 `true`라서 `NaN`과 `2.5`를 둘 다 걸러 낸다. 하지만 `0`, `5`도 정수라 통과하므로, 범위 검사와 **같이** 써야 1·2·3·4만 남는다.
  ```ts
  if (!Number.isInteger(score) || score >= 5 || score <= 0) throw ...
  ```

### index는 0부터 센다

- 프로그래밍에서 index(위치)는 보통 0부터 시작한다. `CONGEST_LEVELS`에서 '여유'의 index는 0이다.
- 우리 점수는 index + 1이라 1부터 시작한다. 이걸 `toLevelIndex`라고 부르면 읽는 사람은 '여유' → 0을 예상한다. 그래서 하는 일대로 `levelToScore` / `scoreToLevel`로 이름을 지었다.
- 같은 이유로 점수의 최댓값(4)은 단계 개수(`CONGEST_LEVELS.length`)와 같다. 위치가 0 ~ 개수−1이니, +1한 점수는 1 ~ 개수다.

### `Record<string, T>`

- "키는 아무 문자열, 값은 `T`"인 객체의 타입이다. `Record<string, Place[]>`는 `{ '중구': Place[], '마포구': Place[], ... }` 모양이다.
- 빈 객체 `{}`만 쓰면 TypeScript는 "칸이 하나도 없는 객체"로 이해해서, `groups['중구'] = []`처럼 칸을 새로 넣을 때 오류가 난다. 그래서 변수를 만들 때 이 타입을 적어 줘야 한다.
  ```ts
  const groups: Record<string, Place[]> = {};
  ```

### `??`와 `??=`

- `A ?? B`: A가 `null`이나 `undefined`이면 B, 아니면 A. `||`와 비슷하지만 `0`이나 `''`는 그대로 A로 둔다는 점이 다르다.
- `a ??= b`: `a = a ?? b`의 줄임. "a가 비어 있을 때만 b를 넣는다".
- `groupByGu`에서는 "이 구의 칸이 없으면 빈 배열을 만들고, 있으면 원래 배열을 그대로 둔다"에 썼다. 이 줄은 칸을 **준비**만 하고, 장소를 실제로 넣는 건 다음 줄 `push`다. 같은 구가 두 번째로 나오면 원래 배열(`[명동]`)이 유지돼서 그 뒤에 `남대문`이 이어 들어간다.
  ```ts
  groups[place.guName] = groups[place.guName] ?? [];
  groups[place.guName].push(place);
  ```

### `Object.entries`

- 객체를 `[키, 값]` 쌍의 배열로 바꿔 준다. `{ 중구: [...], 마포구: [...] }` → `[['중구', [...]], ['마포구', [...]]]`.
- 배열 구조 분해와 같이 쓰면 키와 값을 한 번에 꺼낼 수 있다.
  ```ts
  for (const [guName, guPlaces] of Object.entries(groups)) { ... }
  ```

### 스코프

- 변수는 자기가 만들어진 `{ }` 안에서만 쓸 수 있다. 이 범위를 스코프라고 한다.
- `getGuLevels`에서 `guName`, `guPlaces`, `total`은 바깥 `for`에서 만들어져서, 안쪽 `for`(장소마다 점수를 더하는 반복)가 끝난 뒤에도 바깥 `{ }` 안이라 쓸 수 있다. 그래서 평균을 낼 때 그 구의 장소 개수를 `guPlaces.length`로 구할 수 있다. 반대로 안쪽에서 만든 `guPlace`는 안쪽 `for`를 벗어나면 못 쓴다.

### shadowing

- 안쪽 스코프에서 바깥과 같은 이름의 변수를 다시 만들면, 안쪽에서는 바깥 변수가 가려져 안 보인다.
- `getGuLevels`가 매개변수로 `places`를 받으면서 안쪽 `for`에서도 `const [guName, places]`를 쓰면, 안쪽의 `places`는 "그 구의 장소들"이고 바깥 매개변수(121곳)는 가려진다. 오류는 아니지만 어느 `places`인지 헷갈려서 안쪽을 `guPlaces`로 바꿨다.

### 함수 결과 타입은 추론되지만 적는 게 좋다

- 결과 타입을 안 적어도 TypeScript가 `return` 값을 보고 알아서 정한다(타입 추론). `getGuLevels`는 안 적어도 `Record<string, CongestLevel>`로 추론된다.
- 그래도 적으면 두 가지가 좋다.
  - 함수 첫 줄만 봐도 무엇을 돌려주는지 보인다.
  - 나중에 함수를 고치다 실수로 다른 걸 돌려주면, **이 함수 안에서** 바로 오류가 난다. 안 적으면 결과 타입이 조용히 바뀌고, 이 함수를 쓰는 다른 파일에서 엉뚱한 오류가 난다.
- 반면 변수 `const averageGroups: Record<string, CongestLevel> = {}`의 타입은 **꼭** 적어야 한다(위 `Record` 참고).
