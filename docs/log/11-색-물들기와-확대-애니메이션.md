## 결정과 이유

### 자치구 색은 0.6초 동안, 무작위 순서로 물들게

```tsx
const AMOUNT_OF_GU = 25;
const SHUFFLE_STEP = 7;
const MAX_FILL_DELAY_MS = 400;

function getDelayTime(index: number) {
  const order = (index * SHUFFLE_STEP) % AMOUNT_OF_GU;
  return order * (MAX_FILL_DELAY_MS / (AMOUNT_OF_GU - 1));
}

// 자치구 <path>
style={{ transitionDelay: `${gu ? 0 : delay}ms` }}
className={cn(…, 'transition-colors', 'duration-600', 'motion-reduce:transition-none')}
```

- 원래 데이터가 오면 색이 한 번에 칠해졌다. `transition-colors`로 색이 바뀔 때 600ms 동안 서서히 바뀌게 했다. Tailwind 4의 `transition-colors`는 `fill`과 `stroke`도 포함한다. `duration-600`처럼 숫자는 아무 값이나 쓸 수 있다.
- 처음에는 "서서히 바뀌지 않는다"고 느꼈다. 코드 문제는 아니었다. 회색과 연한 혼잡도 색의 차이가 작고, 바뀌는 곡선이 앞쪽에서 대부분 바뀌어서 눈에 잘 안 띄었다. 개발자 도구 애니메이션 패널을 10% 속도로 놓고 보면 0.6초 동안 바뀌는 게 보인다.
- 25개가 동시에 바뀌는 것보다 **무작위 순서로** 하나씩 물드는 게 보기 좋아서, 자치구마다 0~400ms 사이의 지연을 줬다. 그래서 전체는 최대 1초(지연 400 + 600) 걸린다.
- 지연은 **서울 전체 화면에서만**(`gu`가 `null`일 때) 준다. 자치구를 확대한 상태에서 나머지 자치구가 옅은 색으로 바뀔 때까지 늦게 바뀌면 어색하다. 서울 전체로 돌아올 때도 다시 무작위로 물드는데, 확대 애니메이션과 같이 보니 거슬리지 않아서 그대로 두었다.
- 도안 명세(03의 1-L)는 "400ms 뒤 모든 구 색이 600ms 동안"이었다. 무작위 순서로 바꾼 건 도안과 다르게 한 점이다.

#### 무작위인데 `Math.random`을 쓰지 않은 이유

- 처음에는 렌더링 중에 `Math.random()`으로 지연을 정하려 했다. 그러면 lint가 `react-hooks/purity` 오류를 낸다. React 컴포넌트는 같은 입력이면 같은 결과를 그려야 하는데(순수 함수), `Math.random`은 렌더링할 때마다 다른 값을 내서 그 규칙을 깬다. 다시 렌더링될 때마다(5분 갱신 등) 순서가 바뀌는 문제도 생긴다.
- 대신 **`(index * 7) % 25`** 로 순서를 섞었다. 0, 7, 14, 21, 3, 10, … 처럼 뒤죽박죽이지만 항상 같은 순서다.
- 7을 고른 이유: 25와 **공약수가 1뿐**(서로소)인 수를 곱하고 25로 나눈 나머지를 구하면 0~24가 **한 번씩 빠짐없이** 나온다. 5를 곱하면 0, 5, 10, 15, 20만 반복돼서 여러 자치구가 같은 순서가 된다. 7은 서로소이면서 너무 작지 않아 이웃한 자치구끼리 순서가 멀어진다.

#### 서울대공원은 `transition-[fill]`

- 서울대공원도 처음엔 `transition-colors`를 줬다. 그러자 서울대공원을 골랐을 때 선택 테두리(`stroke-selected`)도 400ms 지연 + 600ms 동안 서서히 나타났다. `transition-colors`에 `stroke`도 들어 있기 때문이다.
- `transition-[fill]`(대괄호 안에 속성을 직접 적는 Tailwind 문법)로 바꿔 **채우기 색만** 서서히 바뀌고 테두리는 바로 나타나게 했다. 서울대공원은 자치구 목록 맨 뒤에 따로 그려서 지연을 400ms(가장 늦게)로 고정했다.

### 확대·축소는 FLIP으로

자치구를 누르면 지도가 0.5초 동안 확대되고, 돌아가면 축소되게 했다. 03 명세의 "viewBox로 그 구까지 확대(0.5초)"를 만드는 방법을 세 가지 생각했다.

| 방법                   | 어떻게                                                                                                         | 문제                                                                                                                                                                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. viewBox를 매 프레임 | JS가 0.5초 동안 매 프레임 viewBox 숫자를 조금씩 바꿈                                                           | CSS transition은 `viewBox` 속성에 걸리지 않아서 JS가 매 프레임 일해야 한다. viewBox가 바뀔 때마다 브라우저가 지도 전체를 다시 계산해 그린다                                               |
| B. 앞으로 키우기       | viewBox는 서울 그대로 두고 transform으로 키운 뒤, **끝나면** viewBox를 바꾸고 transform 제거                   | "끝나는 순간"을 직접 알아내야 하고, 그 순간 두 가지가 같은 프레임에 안 바뀌면 화면이 튄다. 0.5초 동안 주소는 `?gu=중구`인데 viewBox는 서울인 "가짜 상태"라 중간 클릭을 따로 처리해야 한다 |
| **C. FLIP**            | viewBox를 **먼저** 바꾸고, transform으로 이전 화면처럼 보이게 되돌린 뒤, 그걸 풀면서 CSS transition으로 움직임 | 계산이 조금 필요하다                                                                                                                                                                      |

- C로 정했다. **진짜 상태(새 viewBox)를 처음부터 적용**하고, transform은 잠깐 덧씌운 "이전 화면처럼 보이게 하는 겉모습"일 뿐이다. 풀기만 하면 끝이라 끝나는 시점을 알 필요가 없고, viewBox는 언제나 주소와 맞는다.
- JS는 계산과 시작만 하고, 실제 움직임은 CSS transform transition이 맡는다. 시간(0.5초)과 곡선(`ease-out`)도 CSS 클래스에 있다.
- FLIP은 First(처음 모습) → Last(마지막 모습) → Invert(마지막을 처음처럼 보이게 되돌림) → Play(되돌린 걸 풀어 움직임)의 머리글자다.

#### 눈에 보이는 순서와 코드가 일하는 순서가 반대

서울 전체에서 중구를 누르면 코드는 이렇게 일한다.

1. `gu`가 `'중구'`가 되고 React가 viewBox를 중구 범위로 바꾼다. **아직 화면에 그리지 않았다.**
2. 그리기 전에 svg에 transform(`scale(0.22)` 등)을 걸어 줄이고 옮긴다. URL·패널·viewBox는 **이미 중구로 확정**됐지만, 지도 그림만 **아직 클릭하기 전 서울 전체 화면 그대로인 것처럼 보이게** 한다.
3. 첫 프레임은 이 모습으로 그려진다. 사용자 눈에는 클릭 전과 똑같다.
4. 다음 프레임에 transform을 지운다. transition이 켜져 있어서 `scale(0.22)`에서 `scale(1)`까지 0.5초 동안 커진다. 이게 사용자에게 보이는 유일한 움직임이다.

1·2는 화면에 그려지기 전에 끝나서 보이지 않는다. 그래서 "줄였다가 다시 키우는" 두 번의 움직임이 아니라 **확대 한 번**만 보인다.

#### 되돌리는 값 계산

```ts
// viewBox가 상자에 통째로 들어가는 가장 큰 배율 (지도 1단위가 화면에서 몇 px인지)
function getScale(viewBox: ViewBox, boxWidth: number, boxHeight: number) {
  return Math.min(boxWidth / viewBox.width, boxHeight / viewBox.height);
}

// 새 viewBox(to)가 적용된 svg를 이전 viewBox(from)처럼 보이게 되돌리는 값
function getFlipTransform(
  from: ViewBox,
  to: ViewBox,
  boxWidth: number,
  boxHeight: number,
) {
  const s0 = getScale(from, boxWidth, boxHeight);
  const s1 = getScale(to, boxWidth, boxHeight);
  const c0 = getCenter(from);
  const c1 = getCenter(to);
  return { k: s0 / s1, dx: s0 * (c1.x - c0.x), dy: s0 * (c1.y - c0.y) };
}
```

- svg는 viewBox 범위를 칸에 **비율을 유지한 채 통째로 들어가는 가장 큰 크기**로 맞추고 가운데에 둔다(`preserveAspectRatio`의 기본값). 그래서 배율은 가로·세로 중 작은 쪽(`Math.min`)이고, viewBox의 가운데가 칸의 가운데에 온다.
- `k`: 이전 배율 ÷ 새 배율. 서울 → 중구면 약 0.22(줄임), 중구 → 서울이면 약 4.6(키움). 같은 함수로 확대와 축소를 둘 다 처리한다.
- `dx`, `dy`: 두 viewBox 가운데의 차이를 이전 배율로 px로 바꾼 값. transform은 svg 가운데를 기준으로 줄이고 늘리므로, 가운데끼리의 차이만 옮기면 된다.
- 적용은 `translate(dx px, dy px) scale(k)` 순서다. CSS transform은 **오른쪽부터** 적용돼서 먼저 줄이고 그다음 옮긴다. 계산 결과를 숫자로 대입해 확인했을 때 오차는 1e-13 수준이었다.
- 배율에는 칸의 **실제 px 크기**가 필요하다. viewBox 숫자는 지도 좌표(서울 전체가 0~1000)일 뿐 px가 아니다. 칸 크기는 `h-screen w-[calc(100%-360px)]`라는 **규칙**으로만 정해서, 실제 몇 px인지는 브라우저가 그릴 때 정한다. 그래서 `containerRef.current.clientWidth`로 그 순간의 크기를 물어본다. viewBox만 바꾸던 때는 이 계산을 브라우저가 혼자 해서 우리가 알 필요가 없었다.

#### div로 감싼 이유

- svg에 transform을 걸면 svg **자체**가 줄어든다. 10까지처럼 svg가 칸 크기도 맡고 있으면 칸까지 같이 작아진다.
- 그래서 일을 나눴다. 바깥 `<div>`가 칸(크기, `overflow-hidden`으로 바깥 잘라내기)을 맡고 움직이지 않는다. `<svg>`는 `h-full w-full`로 div를 채우고 그 안에서 줄었다 커졌다 한다. 크기도 움직이지 않는 div에서 잰다.
- svg에는 `overflow-visible`을 줬다. 줄어든 동안 svg 칸 바깥에 있는 지도 부분도 그려져야 서울 전체처럼 보인다.

#### 훅으로 분리

```ts
export default function useZoomAnimation(gu: string | null) {
  const viewBox = getViewBox(gu);
  const containerRef = useRef<HTMLDivElement>(null); // 상자 크기를 잴 div
  const svgRef = useRef<SVGSVGElement>(null); // transform을 걸 svg
  const prevViewBoxRef = useRef(viewBox); // 바뀌기 전 viewBox

  useLayoutEffect(() => {
    const container = containerRef.current;
    const svg = svgRef.current;
    if (!container || !svg) return;

    const from = prevViewBoxRef.current;
    const to = getViewBox(gu);
    prevViewBoxRef.current = to;

    // Invert
    const { k, dx, dy } = getFlipTransform(
      from,
      to,
      container.clientWidth,
      container.clientHeight,
    );
    svg.style.transition = 'none';
    svg.style.transform = `translate(${dx}px, ${dy}px) scale(${k})`;

    // Play
    let secondFrameId = 0;
    const firstFrameId = requestAnimationFrame(() => {
      secondFrameId = requestAnimationFrame(() => {
        svg.style.transition = '';
        svg.style.transform = '';
      });
    });

    return () => {
      cancelAnimationFrame(firstFrameId);
      cancelAnimationFrame(secondFrameId);
    };
  }, [gu]);

  return { viewBox, containerRef, svgRef };
}
```

- `getViewBox`는 원래 `seoul-map.tsx`에 있었는데, 확대 애니메이션에서만 쓰는 계산들과 함께 `src/hooks/use-zoom-animation.ts`로 옮겼다. 지도 컴포넌트는 `const { viewBox, containerRef, svgRef } = useZoomAnimation(gu)` 한 줄로 쓴다.
- ref 세 개는 쓰는 목적이 다르다.
  - `prevViewBoxRef`: 값을 **기억**한다. 중구를 누르면 컴포넌트가 다시 실행되면서 `viewBox`는 이미 중구 값이 되고 서울 값은 사라진다. 출발점 계산에 이전 값이 필요해서 ref에 들고 있다가, 꺼내 쓴 뒤 새 값(`to`)으로 바꿔 둔다. 다음 변화 때는 그게 출발점이 된다.
  - `containerRef`: div **요소**를 잡는다. 크기를 물어보려고.
  - `svgRef`: svg **요소**를 잡는다. 렌더링이 끝난 뒤 정확한 순간에 스타일을 넣었다 뺐다 하려고.
- 처음 화면이 그려질 때는 `from`과 `to`가 같아서 `k = 1`, `dx = dy = 0`이 된다. 아무 변화가 없는 transform이라 따로 막지 않았다.

#### `useEffect`가 아니라 `useLayoutEffect`

- `useEffect`는 **화면을 그린 뒤**, `useLayoutEffect`는 **DOM을 바꾼 뒤 화면을 그리기 전**에 실행된다.
- viewBox는 렌더링 결과라 effect보다 먼저 DOM에 들어간다. `useEffect`를 쓰면 확대된 중구가 한 프레임 그려진 뒤에 되돌리게 돼서 순간적으로 번쩍인다. 첫 프레임이 **이미 되돌린 모습**이어야 해서 `useLayoutEffect`를 쓴다.
- `useLayoutEffect`가 끝날 때까지 화면을 그리지 않으므로, 안에서는 계산 몇 줄만 한다.

#### Invert할 때만 transition 끄기

- svg 클래스에 `transition-transform duration-500`이 있으면 transform이 바뀔 때마다 **항상** 0.5초 동안 움직인다. 되돌리기(Invert)까지 움직여 버린다.
- `svg.style.transition = 'none'`을 먼저 걸고 transform을 넣는다. `svg.style.○○`로 넣은 inline 스타일은 클래스보다 우선한다. Play에서 `svg.style.transition = ''`으로 inline 값을 지우면 클래스의 transition이 다시 살아난다.

#### `requestAnimationFrame`을 두 번

- 브라우저는 JS가 실행되는 동안 화면을 그리지 않고, **JS가 끝난 뒤 바뀐 스타일을 한꺼번에** 반영한다. Invert 바로 아래에서 transform을 지우면, 브라우저 입장에서는 "아무것도 안 바뀌었다"가 돼서 transition이 일어나지 않는다. transition은 **그려졌던 값**에서 새 값으로 바꾸는 기능이라, 출발점이 한 번은 그려져야 한다.
- `requestAnimationFrame(함수)`는 "다음 프레임을 그리기 **직전에** 이 함수를 실행해 줘"라는 예약이다.
- 한 번만 예약하면 부족하다. `useLayoutEffect`는 그리기 전에 실행되므로, 거기서 예약한 함수는 **바로 그 첫 프레임** 직전에 실행된다. 출발점이 아직 한 번도 그려지지 않은 시점이다.

```
useLayoutEffect: 출발점 넣기, 예약①
  ↓
예약① 실행        ← 여기서 지우면 출발점이 한 번도 안 그려짐
  ↓
[첫 프레임]        출발점이 그려짐
  ↓
예약② 실행        ← 여기서 지운다
  ↓
[다음 프레임부터]  0.5초 동안 원래 크기로
```

- cleanup에서 두 예약을 모두 `cancelAnimationFrame`으로 취소한다. `setInterval`을 cleanup에서 `clearInterval`하는 것과 같은 방식이다. 출발점을 지우기 전에 `gu`가 또 바뀌면, 이전 예약이 늦게 실행돼 새 출발점을 지워 버리는 걸 막는다. `requestAnimationFrame`은 한 번만 실행되므로 이미 실행된 예약을 취소하면 아무 일도 하지 않는다.

#### 움직임 줄이기

- svg 클래스의 `motion-reduce:transition-none`과 자치구의 같은 클래스로, 운영체제에서 "동작 줄이기"를 켠 사용자는 확대·축소와 색 변화가 즉시 일어난다. 개발자 도구 렌더링 탭의 `prefers-reduced-motion: reduce`로 확인했다.

#### 확인한 동작

- 서울 전체에서 중구 클릭 → 0.5초 동안 확대
- [← 서울 전체] → 0.5초 동안 축소
- 흐려진 옆 자치구 클릭, 브라우저 뒤로 가기·앞으로 가기 → 똑같이 움직임 (`gu`가 바뀌는 모든 경우에 effect가 실행되므로)
- 움직임 줄이기 → 바로 바뀜

### 보류한 것

- **새로 나타나는 장소를 서서히 보이게**: 자치구를 누르면 장소들이 작은 크기로 먼저 확 나타나고 그대로 확대된다. `@keyframes`로 투명도 0 → 1을 주고 `<g key={gu}>`로 자치구가 바뀔 때마다 다시 재생하는 방법을 정해 뒀지만, 직접 보니 거슬리지 않아 하지 않았다.
- **움직이는 도중에 다른 곳을 누를 때**: 움직이던 위치가 아니라 직전 화면에서 다시 출발해서 한 번 툭 튈 수 있다. 직접 써 보고 거슬리면 다룬다.
- **매 프레임 viewBox 방식과의 비교 측정**: FLIP을 고른 근거를 숫자로 보여 줄 수 있지만, 비교용 코드를 따로 만들어야 해서 지원서 제출 전에는 하지 않았다.
- **메타데이터·링크 미리보기**: SEO 감점(`meta-description`)을 없앨 작업이지만 지원서 제출 전 범위에서 뺐다.

## 문제와 해결

### `transitionDelay`에 숫자를 넣어 타입 오류

- **원인**: `style={{ transitionDelay: gu ? 0 : delay }}`처럼 숫자를 넣었다. React의 `style` 타입에서 `transitionDelay`는 **문자열만** 받는다. 시간은 `ms`나 `s` 단위가 꼭 붙어야 해서다. 숫자를 넣으라는 건 처음에 잘못 안내받은 것이었다.
- **해결**: `` `${gu ? 0 : delay}ms` ``. 템플릿 문자열로 단위를 붙인다.

### 지연 조건이 반대

- 처음에 `gu ? delay : 0`으로 써서, 서울 전체에서는 한 번에 물들고 자치구를 확대했을 때 늦게 바뀌었다. `gu`가 있으면(확대 중) 0이어야 하므로 `gu ? 0 : delay`로 고쳤다.

### `getScale`에 viewBox 크기를 넣음

- **증상**: `k`가 1이 나와서 아무것도 되돌려지지 않았고, 한 번 고친 뒤에는 0.803이 나왔다.
- **원인**: `getScale(viewBox, viewBox.width, viewBox.height)`처럼 **칸 크기 자리에 viewBox 크기**를 넘겼다. 그러면 `viewBox.width / viewBox.width`라 항상 1이다. 한쪽만 고쳤을 때는 s0만 맞고 s1이 1이라 0.803(서울 전체 배율)이 나왔다.
- **해결**: `s0`, `s1` 둘 다 `boxWidth`, `boxHeight`(div의 `clientWidth`, `clientHeight`)를 넣는다. 고친 뒤 중구는 `k ≈ 0.218`, `dx ≈ 38.3`, `dy ≈ 17.9`.

### `getCenter`의 y에 `/ 2`가 빠짐

- `y: viewBox.y + viewBox.height`로 써서 가운데가 아니라 아래 끝이 나왔다. `/ 2`를 붙였다.

### JSX 안에 `console.log`를 넣어 타입 오류

- 계산 값을 보려고 JSX 안에 `{console.log(…)}`를 넣었더니 `Type 'void' is not assignable to type 'ReactNode'`가 났다. `console.log`는 아무것도 돌려주지 않는데(`void`), JSX의 `{}` 안은 화면에 그릴 값이어야 한다. 값을 볼 때는 JSX 바깥(return 위)에서 찍는다.

### div와 svg의 클래스를 반대로 둠

- 처음 감쌀 때 크기와 `overflow-hidden`이 svg에 남아 있었다. 그러면 svg가 줄어들 때 칸도 같이 줄어든다. 크기·`overflow-hidden`은 div로, svg는 `h-full w-full overflow-visible`로 바꿨다.

### transition을 켜자 반대 방향으로 움직임

- **증상**: svg에 `transition-transform duration-500` 클래스를 넣자, 중구를 누르면 확대된 중구가 먼저 보였다가 서울 전체 크기로 **줄어들고** 멈췄다. 서울 전체로 돌아갈 때는 서울이 보였다가 중구 확대처럼 커지고 멈췄다.
- **원인**: viewBox는 transition 없이 즉시 바뀌는데, transform은 transition 때문에 **직전 값 `scale(1)`에서 출발**해 서서히 바뀐다. 첫 프레임은 `viewBox 중구 + scale(1)`이라 확대된 중구가 보이고, 그다음 되돌리는 과정(Invert)이 0.5초짜리 애니메이션이 됐다. 즉 출발점으로 **가는** 움직임이 보인 것이다.
- **해결**: Invert 직전에 `svg.style.transition = 'none'`. 출발점으로 즉시 가서 멈춘다. 그 상태에서 Play를 써서 출발점에서 **돌아오는** 움직임만 보이게 했다.

## 확인한 사실

- 중구 viewBox는 `x 423, y 433, width 249, height 178`(bbox에 긴 변의 30% 여백). 칸이 920×803px일 때 서울 전체는 지도 1단위가 약 0.8px, 중구는 약 3.7px라서 약 4.6배 크게 보인다.
- `(index * 7) % 25`는 index 0~24에 대해 0~24를 한 번씩 낸다(7과 25가 서로소).
- 개발자 도구가 한국어면 명령 메뉴에서 `Animations` 대신 `애니메이션`으로 찾는다.
- 성능 탭 기록 중 클릭할 때마다 네트워크 줄에 `localhost` 요청이 하나 보이고, 그 요청이 끝난 뒤 React 작업이 시작됐다. `router.push`가 서버에 무언가를 받으러 가는 것으로 보이는데, 요청 내용은 아직 확인하지 않았다. Next 문서(`04-linking-and-navigating.md`)에 따르면 `window.history.pushState`로 주소를 바꿔도 `useSearchParams`가 따라 바뀌어서, 확인 후 개선 후보로 본다.

## 새로 배운 것

### SVG의 viewBox

- path의 `d`는 도형을 **좌표로** 적어 둔 것이다. 이 좌표는 px가 아니라 그 svg만의 좌표다.
- viewBox가 없으면 svg 칸의 왼쪽 위가 (0,0)이고 좌표 1 = 1px다. svg에 크기를 안 줘도 브라우저가 기본 칸(viewBox가 없으면 300×150px)을 만들어서 기준은 항상 있다.
- viewBox는 **좌표 공간에서 어느 범위를 칸에 보여줄지** 고른다. 고른 범위는 칸에 맞게 비율을 유지한 채 늘어나거나 줄어든다. 같은 `d`라도 viewBox 범위를 좁히면 크게(확대), 넓히면 작게(축소) 보인다.
- 칸 크기(className의 크기 클래스)와 viewBox는 하는 일이 다르다. viewBox는 **무엇을**(어느 범위를), 크기는 **얼마나 크게**를 정한다. 서울 전체가 다 보이는 건 viewBox가 `0 0 1000 1000`이기 때문이고, 칸 크기와는 관계없다. 칸이 정사각형이 아니면 양옆에 빈 공간이 생긴다.

### transition과 `@keyframes`

- transition은 **값이 바뀔 때** 그 사이를 채워 준다. 출발값과 도착값이 같으면 아무 일도 없다.
- `@keyframes` 애니메이션은 **요소가 나타날 때**(클래스가 처음 붙을 때) 정해 둔 움직임을 재생한다. 장소가 "새로 나타나는" 것에는 이쪽이 맞다.

### ref는 두 가지 용도

- **값 기억**: 다시 렌더링돼도 지워지지 않는 상자. 값을 바꿔도 다시 렌더링을 일으키지 않는다(`prevViewBoxRef`).
- **DOM 요소 잡기**: `ref={…}`로 연결하면 React가 화면에 요소를 만든 뒤 `.current`에 넣어 준다. effect 안에서 꺼내 쓴다(`containerRef`, `svgRef`). 처음엔 요소가 없어서 `null`이다.

### 브라우저는 JS가 끝난 뒤 한꺼번에 그린다

- JS 안에서 스타일을 여러 번 바꿔도 화면에는 **마지막 값**만 그려진다. 중간 값을 화면에 한 번 그리게 하려면 프레임을 넘겨야 하고, 그때 `requestAnimationFrame`을 쓴다.
