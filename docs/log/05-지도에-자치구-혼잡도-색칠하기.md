## 결정과 이유

### 데이터는 TanStack Query로 받고, 5분마다 다시 부른다

- 서울시 데이터는 5분마다 바뀌고 서버 캐시도 5분이다(`04` 문서). 화면을 켜 둔 사람도 새 값을 보게 하려고 `refetchInterval: 5 * 60 * 1000`을 줬다.
- `useEffect` + `fetch`로 직접 만들면 로딩 상태, 실패 상태, 재시도, 주기적 다시 부르기, 같은 요청 합치기를 모두 직접 짜야 한다. TanStack Query는 이것들을 기본으로 해 준다.
- 원래 `04` 문서에는 "`/api/places`를 **한 번** 불러"라고 적혀 있었다. 실제 동작에 맞게 "5분마다 다시 부른다"로 고쳤다.
- devtools(`@tanstack/react-query-devtools`)는 지금 필요하지 않아서 설치하지 않았다.

### `QueryClient`는 `useState`로 한 번만 만든다

```tsx
'use client';
export default function Providers({ children }: ProviderProps) {
  const [queryClient] = useState(() => new QueryClient());
  return (
    <QueryClientProvider client={queryClient}>{children}</QueryClientProvider>
  );
}
```

- `QueryClient`는 받아 온 데이터(캐시)를 들고 있는 객체다. 컴포넌트 함수 안에서 `new QueryClient()`를 그냥 부르면 다시 그려질 때마다 새 객체가 생겨서 캐시가 날아간다.
- `useState(() => ...)`처럼 **함수**를 넘기면 React는 그 함수를 첫 렌더 때 한 번만 실행하고, 그 뒤에는 저장해 둔 값을 돌려준다. 그래서 `QueryClient`가 하나로 유지된다.
- 이 파일에는 `'use client'`가 필요하다. Provider는 context(아래 컴포넌트에 값을 몰래 넘겨 주는 React 기능)를 쓰는데, context와 훅은 클라이언트 컴포넌트에서만 동작하기 때문이다. 그래도 `{children}`으로 받은 `page.tsx`는 서버 컴포넌트로 그대로 남는다. 클라이언트 컴포넌트가 children을 **받아서 넘겨만** 주는 것은 괜찮다.

### 훅은 `useQuery` 결과를 통째로 돌려준다

```ts
export default function usePlaces() {
  return useQuery({
    queryKey: ['places'],
    queryFn: async (): Promise<Place[]> => {
      const res = await fetch('/api/places');
      if (!res.ok) {
        throw new Error(`${res.status} 에러`);
      }
      return res.json();
    },
    refetchInterval: 5 * 60 * 1000, // 5분
  });
}
```

- `data`만 꺼내서 돌려주면, 화면에서 실패 여부나 다시 부르기(`refetch`)를 쓸 수 없다. 결과 객체를 통째로 돌려주면 쓰는 쪽이 필요한 것만 구조 분해로 꺼낸다.
- `fetch`는 서버가 404나 500을 돌려줘도 **오류를 던지지 않는다**. 네트워크가 아예 끊겼을 때만 실패한다. 그래서 `res.ok`(상태 코드 200~299면 `true`)를 직접 보고 아니면 `throw`해야 TanStack Query가 "실패"로 안다.
- `queryFn`의 결과 타입 `Promise<Place[]>`를 적은 이유: `res.json()`의 타입은 `any`다. 결과 타입을 안 적으면 `data`도 `any`가 될 수 있다. 적어 두면 `data`가 `Place[] | undefined`로 잡힌다(확인용 tsc 설정으로 직접 확인했다).

### 훅 파일 이름도 kebab-case (`use-places.ts`)

- 훅 파일은 camelCase(`usePlaces.ts`)가 흔하다는 의견이 있어서 shadcn을 쓰는 공개 저장소 15곳을 찾아봤다. 저장소들은 **컴포넌트 파일 이름 규칙에 훅 파일 이름을 맞추는** 경우가 대부분이었다. 컴포넌트를 kebab-case로 쓰면 훅도 kebab-case였다.
- shadcn이 주는 훅도 `use-mobile`이다. 우리는 컴포넌트를 kebab-case로 쓰므로 훅도 맞췄다. 함수 이름은 그대로 `usePlaces`(camelCase)다. `06` 문서에 적었다.

### 자치구 색은 세 갈래로 정한다

```ts
const LEVEL_COLOR: Record<CongestLevel, string> = {
  여유: 'fill-congestion-free',
  보통: 'fill-congestion-normal',
  '약간 붐빔': 'fill-congestion-busyish',
  붐빔: 'fill-congestion-busy',
};

function getFillColor(
  guLevels: Record<string, CongestLevel> | undefined,
  guName: string,
): string {
  const level = guLevels?.[guName];
  return level
    ? LEVEL_COLOR[level] // ① 단계가 있음 → 혼잡도 색
    : guLevels
      ? 'fill-congestion-none' // ② 데이터는 왔는데 이 자치구만 없음 → 회색 (#E6E6E6)
      : 'fill-map-empty'; // ③ 데이터가 아직 없음(로딩·실패) → 거의 흰색 (#FBFAF8)
}
```

- 처음에는 `level ? 색 : 'fill-map-empty'` 두 갈래였다. 이러면 중랑구처럼 **장소가 하나도 없는 자치구**와 **아직 데이터가 안 온 상태**를 구별하지 못한다. 둘 다 `level`이 `undefined`이기 때문이다.
- 구별하는 기준은 `guLevels` 자체가 있느냐다. `guLevels`가 있는데 이 자치구의 칸이 없으면 ②, `guLevels`가 아예 없으면 ③이다.
- `LEVEL_COLOR`를 `Record<CongestLevel, string>`으로 적은 이유: 키가 네 단계로 정해져 있어서, 하나라도 빠뜨리거나 오타가 나면 TypeScript가 바로 알려 준다.
- `getFillColor`를 컴포넌트 밖 함수로 뺀 이유: 25개 자치구와 서울대공원 두 곳에서 같은 규칙을 쓰기 때문이다. 함수가 컴포넌트의 값에 기대지 않고 인자만 받으므로 밖에 둘 수 있다.

### 서울대공원(과천)은 `guName`으로 색을 찾는다

```tsx
const seoulGrandPark = placeList.find((place) => place.code === 'POI100');
...
{seoulGrandPark && (
  <path
    d={seoulGrandPark.d}
    className={`${getFillColor(guLevels, seoulGrandPark.guName)} stroke-map-line`}
  />
)}
```

- 서울대공원은 서울 밖(과천시)이라 `districts.json`(서울 25개 자치구)에 없다. 모양(`d`)은 `places.json`에서 장소코드 `POI100`으로 찾는다. 이름보다 코드가 바뀔 일이 적어서 코드로 찾았다.
- 서울대공원의 `guName`은 `'과천시'`다. 어제 `getGuLevels`에서 확인했듯이 과천시는 서울대공원 하나만 있는 묶음이 되므로, `guLevels['과천시']`가 곧 서울대공원의 단계다. 그래서 따로 계산하지 않고 `getFillColor`에 `guName`을 넘긴다. `'과천시'`를 직접 적지 않고 `seoulGrandPark.guName`을 쓰면, 데이터와 화면의 이름이 어긋날 일이 없다.
- `find`는 못 찾으면 `undefined`를 돌려준다. 그래서 `seoulGrandPark &&`로 감싸서, 있을 때만 그리고 그 안에서는 `undefined`가 아니라고 TypeScript가 알게 했다.

### 실패 안내는 "한 번이라도 실패를 끝까지 겪었는지"(`errorUpdateCount > 0`)로 보여 준다

```tsx
const { data, errorUpdateCount, isFetching, refetch } = usePlaces();

let message: React.ReactNode;
if (data) {
  message = null; // 추후에 TOP5 표시 예정
} else if (errorUpdateCount > 0) {
  message = <ErrorState onRetry={() => refetch()} isRetrying={isFetching} />;
} else {
  message = '불러오는 중';
}
```

- 처음 생각은 `isError`나 `status === 'error'`였다. 그런데 [다시 시도]를 누르면 TanStack Query는 데이터가 없는 상태에서 `status`를 다시 `'pending'`으로 돌리고 오류도 지운다(`query-core/build/modern/query.js`의 `fetchState`에서 확인). 그러면 누르는 순간 실패 안내가 사라지고 "불러오는 중"으로 바뀌었다가, 다시 실패하면 안내가 돌아온다. 화면이 깜빡이고 버튼도 사라진다.
- `errorUpdateCount`는 "실패가 확정된 횟수"이고, 다시 시도해도 **줄어들지 않는다**. 그래서 한 번 실패한 뒤에는 다시 시도하는 동안에도 실패 안내가 그대로 남는다.
- 버튼 상태는 `isFetching`(지금 요청 중인지)으로 정한다. 다시 시도하는 동안 버튼 글자를 "다시 불러오는 중"으로 바꾸고 `disabled`로 막는다. 여러 번 눌러 요청이 쌓이는 것을 막고, 누른 게 먹혔다는 것을 보여 준다.
- `data`를 맨 먼저 검사하는 이유: 한 번 받은 뒤 5분 갱신이 실패하면 `data`는 남아 있고 `isError`만 `true`가 된다. 이때는 실패 안내 대신 받아 둔 데이터를 계속 보여 주는 게 맞다(`03` 문서: "한 번이라도 성공한 데이터가 있으면 그걸 보여주고"). 오래된 데이터 안내(1-S)는 11/9 이후.
- `message`를 `useState`로 두지 않은 이유: `message`는 `data`, `errorUpdateCount`에서 **계산되는 값**이다. 이미 있는 값에서 계산할 수 있는 것을 state로 따로 두면 두 값이 어긋날 수 있다. 그리고 렌더 중에 `setMessage`를 부르면 다시 렌더 → 다시 `setMessage`가 반복된다. 그래서 그냥 변수로 계산한다.

### 실패 안내 도안을 바꿨다 (1-E)

- 위의 영어 eyebrow `ERROR · NO DATA`를 뺐다.
- 문구는 "혼잡도 데이터를 불러오지 못했어요." / "잠시 후 다시 시도해 주세요."로 바꿨다. 원래 도안은 "지금은 혼잡도를 불러오지 못했어요" / "서울시 데이터 서버가 응답하지 않아요. 지도 모양은 그대로 볼 수 있어요."였다.
- 다시 불러오는 동안 버튼은 "다시 불러오는 중" + `disabled`. `03` 문서에 적었다.

### 상태 안내는 지도가 아니라 패널 몫이다

- 지도는 데이터가 있든 없든 **항상** 그린다. 데이터가 없으면 색만 없다(`fill-map-empty`). 지도에 필요한 것은 `data` 하나뿐이다.
- "불러오는 중", 실패 안내, TOP 5는 전부 패널 안에 나온다. 그래서 상태 조건문을 `SeoulMap`에서 `FloatingPanel`로 옮겼다. `ErrorState`는 props만 받는 부품이라 옮겨도 고칠 게 없었다.
- 성공 갈래는 `null`(아무것도 안 그림)이다. 처음에 확인용으로 넣었던 `'121곳'` 글자는 지웠고, 이 자리에는 MVP 이후 TOP 5가 들어온다.

### 패널은 `aside` + `absolute`

```tsx
<aside className="absolute top-5 right-5 bottom-5 flex w-85 flex-col gap-4 overflow-auto rounded-lg border border-border-soft bg-card p-5 shadow-panel">
  <h2 className="text-lg font-bold">서울 전체</h2>
  <div className="flex flex-1">{message}</div>
</aside>
```

- 디자인 시스템(DS-3)의 이름 그대로 `FloatingPanel`이다: 오른쪽 20px 띄워 위·아래 꽉, 폭 340, 안쪽 20, 6px 모서리 + 패널 그림자, 내용이 길면 패널 안에서만 스크롤.
- `aside`는 "본문 옆에 붙는 보조 내용"이라는 뜻의 HTML 태그다. `div`와 모양은 같지만 스크린리더가 이 영역을 보조 영역으로 알려 줄 수 있다.
- `absolute`는 가장 가까운 `relative` 조상을 기준으로 위치를 잡는다. 그래서 `page.tsx`의 `<main>`에 `relative`를 줬다. `<main>`에는 페이지 바탕색 `bg-background`와 화면 높이 `h-screen`도 줬다.
- 지도는 아직 화면 전체 폭이라 동쪽 자치구 일부(강동구·송파구 쪽)가 패널 아래에 깔린다. 도안처럼 지도를 패널 왼쪽 영역에 맞추는 건 이번 범위가 아니어서 그대로 뒀다.

### 그림자는 토큰으로 (`shadow-panel`)

- 패널 그림자 값(`0 1px 2px rgba(60,45,30,0.06), 0 10px 30px rgba(60,45,30,0.10)`)이 `tokens.md`에는 있었지만 `globals.css`에는 없었다.
- Tailwind v4에서는 `@theme` 안에 `--shadow-이름`을 넣으면 `shadow-이름` 클래스가 생긴다. 색의 `--color-이름` → `bg-이름`과 같은 규칙이다. `--shadow-panel`을 넣어 `shadow-panel`로 쓴다.
- `shadow-[...]`처럼 값을 클래스에 바로 적는 방법도 있지만, 모바일 바텀시트 그림자도 같은 계열이라 이름을 붙여 두는 게 나중에 찾고 바꾸기 쉽다.

### `border-border-soft`는 이름이 겹쳐도 그대로 쓴다

- 앞의 `border-`는 Tailwind의 "테두리 색" 접두사이고, 뒤의 `border-soft`는 우리 토큰 이름(`--color-border-soft`)이다. 그래서 `border`가 두 번 나온다.
- 토큰 이름은 "어디에 쓰는 색인지"를 말한다. `soft`로 줄이면 클래스는 짧아지지만 `bg-soft`, `text-soft`도 같이 생겨서 무엇에 쓰는 색인지 알 수 없다. shadcn도 `border-border`, `bg-background`처럼 같은 방식이다. `tokens.md`와 이름이 같아야 도안과 맞춰 보기도 쉽다.
- `border`(두께 1px + 실선)와 `border-border-soft`(색)는 하는 일이 달라서 둘 다 필요하다.

### 버튼 커서는 전역으로 pointer

- Tailwind v4는 기본 스타일 초기화(preflight)에서 버튼 커서를 브라우저 기본값(화살표)으로 둔다. v3에서는 손가락(pointer)이었다. shadcn `Button`에도 `cursor-pointer`가 없다.
- 버튼마다 `cursor-pointer`를 붙이면 언젠가 하나는 빠뜨린다. 그래서 `globals.css`의 `@layer base`에 한 번만 넣었다. Tailwind v4 업그레이드 안내에도 같은 방법이 있다.
  ```css
  button:not(:disabled),
  [role='button']:not(:disabled) {
    cursor: pointer;
  }
  ```
- `:not(:disabled)`는 "비활성이 아닌 버튼만"이다. 누를 수 없는 버튼에 손가락 모양이 나오면 누를 수 있는 것처럼 보이기 때문이다.

### MVP 기능을 먼저, 버튼 모양 세부는 나중에

- 도안 메모의 버튼 상태(hover 검정 바탕, focus 주황 테두리, 다시 불러오는 중 회색 + 아이콘 회전)는 11/9 이후로 미뤘다. 11/8 배포까지 남은 일(주소 상태, 자치구 확대, 장소 상세·예측 차트, 배포)이 더 급하다.

## 문제와 해결

### 실패 화면을 보려고 `/api/placesx` 주소로 들어감 → Next 404 페이지

- 브라우저 주소창에 잘못된 주소를 치면 **페이지 자체**가 없어서 Next 기본 404 페이지가 뜬다. 우리 화면이 아예 안 그려진다.
- **해결**: 화면은 `/`로 열고, 훅 안의 `fetch('/api/places')` 문자열만 잠깐 `/api/placesx`로 바꿔서 시험했다. 그러면 화면은 그대로 뜨고 데이터 요청만 404가 난다. 시험 뒤에 되돌렸다.

### 렌더 중 `setMessage` → 무한 렌더

- **원인**: `message`를 `useState`로 만들고 컴포넌트 본문에서 `setMessage`를 불렀다. state가 바뀌면 다시 렌더하고, 다시 렌더하면 또 `setMessage`를 부른다.
- **해결**: state를 지우고 `let message`로 그때그때 계산했다(위 "결정과 이유").

### `<p>` 안에 `<div>` → hydration 경고 ("4 Issues")

- **원인**: `<p>{message}</p>` 안에 `ErrorState`(`div` + `p` + 버튼)가 들어갔다. HTML 규칙상 `p` 안에는 `div`나 또 다른 `p`를 넣을 수 없다. 브라우저가 HTML을 읽으면서 `p`를 강제로 닫아 버려서, 서버가 만든 HTML과 React가 기대한 모양이 달라진다(hydration 불일치).
- **해결**: `p`로 감싸지 않고 `{message}`를 바로 넣었다. 지금은 패널의 내용 칸 `div` 안에 들어간다.

### [다시 시도]를 눌러도 반응 없음

- **원인**: `onRetry={() => refetch}`. 화살표 함수가 `refetch` 함수를 **돌려주기만** 하고 부르지 않았다.
- **해결**: `onRetry={() => refetch()}`. 괄호가 있어야 실행된다.
- `onRetry={refetch}`로 바로 넘기는 방법도 생각했지만 쓰지 않았다. 버튼 `onClick`은 클릭 이벤트 객체를 첫 인자로 넘기는데, `refetch`는 첫 인자를 옵션으로 받는다. 엉뚱한 값이 옵션으로 들어가게 된다.

### 실패 안내가 패널 가운데로 안 감

- **원인**: `ErrorState`의 바깥 `div`에 `flex-1`(남은 공간 다 차지)을 줬지만, 부모인 내용 칸 `div`가 flex가 아니었다. `flex-1`은 **flex 부모의 바로 아래 자식**일 때만 동작한다.
- **해결**: 내용 칸 `div`를 `flex flex-1`로 했다. 내용 칸이 패널의 남은 높이를 다 차지하고(`aside`가 `flex flex-col`이라서), 그 안에서 `ErrorState`도 남은 공간을 다 차지한 뒤 가운데 정렬된다.
- 처음에는 `flex h-full`로 했다. 화면에서는 맞게 나왔지만 이유가 우연이었다. `h-full`은 부모 높이의 100%라서 제목과 간격만큼 넘쳐야 하는데, flex 자식의 기본값 `flex-shrink: 1` 때문에 브라우저가 줄여 준 것이다. `flex-1`이 "남은 공간을 다 차지"라는 의도를 그대로 보여 줘서 바꿨다.

## 확인한 사실

- 실패 흐름: `/api/placesx`로 바꾸면 약 7초 뒤 실패 안내가 뜬다(첫 시도 + 재시도 3번, 1초·2초·4초 대기). [다시 시도]를 누르면 버튼이 "다시 불러오는 중"으로 바뀌고 막혔다가, 다시 실패하면 "다시 시도"로 돌아온다. 그동안 실패 안내는 사라지지 않는다.
- 실패 상태에서 지도는 모든 자치구가 `fill-map-empty`(거의 흰색)로, 모양만 보인다.
- 자정 무렵 데이터는 121곳 중 119곳이 '여유'라서 색 차이가 거의 안 보였다. 네 단계 색과 회색은 임시 가짜 `guLevels`로 확인하고 지웠다.
- 중랑구는 장소가 없어서 `fill-congestion-none`(회색), 서울대공원은 과천시 묶음 값으로 칠해진다.
- 개발 모드에서 콘솔 로그가 두 번씩 찍히는 건 React Strict Mode(개발 중에 일부러 두 번 렌더해 실수를 찾는 모드, Next 기본 켜짐) 때문이다. `installHook.js`로 찍힌 줄은 React DevTools가 다시 보여 준 것이다.
- `/api/places`는 빌드 결과 Static(○)이고 서버 캐시는 그대로다. 브라우저의 5분 다시 부르기는 이 캐시를 읽는다.

## 새로 배운 것

### TanStack Query의 `queryKey`

- 요청 결과를 저장하는 칸의 이름이다. `['places']`처럼 배열로 적는다.
- 같은 `queryKey`를 쓰는 `useQuery`가 여러 컴포넌트에 있어도 요청은 **한 번만** 가고, 결과는 같은 칸에서 같이 읽는다. 그래서 `SeoulMap`과 `FloatingPanel`이 각자 `usePlaces()`를 불러도 `/api/places`는 한 번만 불린다. 한쪽이 다시 부르면 다른 쪽도 새 값을 받는다.
- 나중에 자치구별로 따로 부르는 요청이 생기면 `['places', guName]`처럼 키를 나눈다.

### TanStack Query 기본 동작 (오늘 쓴 것)

- **재시도 `retry: 3`**: 실패하면 3번 더 시도한다. 기다리는 시간은 1초 → 2초 → 4초로 늘어난다. 그래서 실패 안내가 뜨기까지 약 7초 걸린다.
- **`refetchInterval`**: 정한 간격마다 다시 부른다. 우리는 5분.
- **`refetchIntervalInBackground: false`**: 브라우저 탭이 뒤에 숨어 있으면 주기적 다시 부르기를 쉰다. 아무도 안 보는 화면 때문에 서버를 부르지 않는다.
- **`refetchOnWindowFocus: true`**: 다른 탭에 갔다가 돌아오면, 데이터가 오래된 상태(기본 `staleTime: 0`이라 받자마자 오래된 것으로 친다)일 때 바로 다시 부른다.
- **다시 부르기가 실패해도 `data`는 남는다**: 한 번 성공한 뒤 실패하면 `data`는 그대로이고 `isError`만 `true`가 된다.

### `status`, `isFetching`, `errorUpdateCount`의 차이

| 값                 | 뜻                                                       | 다시 시도를 누르면                     |
| ------------------ | -------------------------------------------------------- | -------------------------------------- |
| `status`           | 데이터 기준 상태: `'pending'` / `'error'` / `'success'`  | 데이터가 없으면 `'pending'`으로 돌아감 |
| `isFetching`       | 지금 요청이 나가 있는지 (첫 요청, 재시도, 5분 갱신 모두) | 요청 중에 `true`                       |
| `errorUpdateCount` | 실패가 확정된 횟수 (재시도 3번까지 다 실패해야 1 증가)   | 그대로 (줄지 않음)                     |

- 그래서 "실패 안내를 보여 줄지"는 `errorUpdateCount > 0`, "버튼을 막을지"는 `isFetching`으로 나눠서 정했다.

### 서버 컴포넌트와 클라이언트 컴포넌트

- Next App Router에서 컴포넌트는 기본이 **서버 컴포넌트**다. 서버에서 HTML로 만들어지고, 브라우저로 JS가 가지 않는다. 대신 `useState`, `useEffect`, context, 클릭 같은 브라우저 기능을 쓸 수 없다.
- 파일 맨 위에 `'use client'`를 쓰면 **클라이언트 컴포넌트**가 된다. 브라우저에서도 실행돼서 훅과 이벤트를 쓸 수 있다.
- 오늘 `providers.tsx`, `seoul-map.tsx`, `floating-panel.tsx`가 클라이언트 컴포넌트다(TanStack Query 훅과 context를 써서). `page.tsx`와 `layout.tsx`는 서버 컴포넌트로 남았다.
- `ErrorState`에는 `'use client'`가 없지만 클라이언트에서 돈다. 클라이언트 컴포넌트(`FloatingPanel`)가 **import해서 쓰는** 컴포넌트는 같이 클라이언트 쪽이 되기 때문이다. 반면 `children`으로 **받아서 넘기기만** 하는 컴포넌트는 서버 컴포넌트로 남는다.

### Tailwind 클래스는 완전한 글자로 적어야 한다

- Tailwind는 빌드할 때 소스 코드를 **글자 그대로** 훑어서 쓰인 클래스만 CSS로 만든다. 코드를 실행하지 않는다.
- `` `fill-congestion-${level}` ``처럼 조각을 이어 붙이면 소스에 `fill-congestion-free`라는 완성된 글자가 없어서 CSS가 만들어지지 않는다.
- 그래서 `LEVEL_COLOR`에 클래스 이름을 **통째로** 적었다. 객체에서 고르는 건 실행 중이어도, 글자 자체는 소스에 다 있다.

### `Record<CongestLevel, string>`과 `Record<string, CongestLevel>`의 차이

- `Record<CongestLevel, string>`: 키가 네 단계로 **정해져 있다**. 하나라도 빠지면 오류가 난다. `LEVEL_COLOR`에 썼다.
- `Record<string, CongestLevel>`: 키가 **아무 문자열**이다. TypeScript는 `guLevels['중랑구']`가 항상 있다고 보고 `CongestLevel`로 알려 준다. 실제로는 칸이 없어서 `undefined`가 나온다. 그래서 `level ? ... : ...`처럼 직접 있는지 확인해야 한다.

### `| undefined`와 선택 매개변수 `?`

- `guLevels: Record<...> | undefined`: 인자를 **반드시 넘기되**, 그 값이 `undefined`일 수 있다.
- `guLevels?: Record<...>`: 인자를 **아예 안 넘겨도** 된다.
- `getFillColor`는 항상 `guLevels`를 넘기고 그 값이 비어 있을 수 있는 것이라 `| undefined`가 맞다.

### `&&`로 조건부 렌더링 (narrowing)

- JSX에서 `A && <B />`는 A가 참일 때만 B를 그린다. A가 `undefined`면 아무것도 그리지 않는다.
- TypeScript는 `&&` 오른쪽에서 A가 `undefined`가 아님을 안다. 이렇게 조건으로 타입 범위를 좁히는 것을 narrowing이라고 한다. `seoulGrandPark && (...)` 안에서 `seoulGrandPark.guName`을 `?.` 없이 쓸 수 있는 이유다.

### `role="alert"`

- 스크린리더에게 "이 영역은 중요한 알림이니 바로 읽어 줘"라고 알려 주는 속성이다. 실패 안내가 화면에 나타나면 스크린리더가 사용자가 다른 곳에 있어도 읽어 준다.
- lucide 아이콘(`<RotateCw />`)은 기본으로 `aria-hidden="true"`가 붙어서 스크린리더가 읽지 않는다. 버튼 이름은 옆 글자("다시 시도")가 된다.

### `flex-1`

- flex 부모 안에서 "남은 공간을 다 차지해"라는 뜻이다(`flex: 1 1 0%`).
- **부모가 flex일 때만** 동작한다. 오늘 `ErrorState`의 `flex-1`이 안 먹었던 이유가 부모(내용 칸 `div`)가 flex가 아니어서였다.
- 오늘 구조는 flex가 두 번 겹친다. `aside`(flex-col) → 내용 칸 `div`(`flex-1`로 세로 남은 공간 차지, 자기도 `flex`) → `ErrorState`(`flex-1`로 그 공간 다 차지, `items-center justify-center`로 가운데 정렬).

### Tailwind 숫자 크기 = 숫자 × 4px

- `p-5` = 20px, `top-5` = 20px, `gap-4` = 16px, `w-85` = 340px, `max-w-60` = 240px.
- v4에서는 `w-85`처럼 정해진 칸에 없는 숫자도 같은 계산으로 만들어 준다. 4로 나누어떨어지지 않는 값(13px 글자 등)은 `text-[13px]`처럼 대괄호로 적는다.

### shadcn `Button`에 `className`으로 덮어쓰기

- shadcn `Button`은 기본 클래스와 `variant` 클래스에 내가 넘긴 `className`을 `cn()`으로 합친다. `cn`은 겹치는 Tailwind 클래스(예: `rounded-lg`와 `rounded-sm`)가 있으면 **뒤에 온 것**만 남긴다.
- 그래서 `variant="outline"`은 그대로 두고 도안과 다른 부분(`rounded-sm`, `border-input`, `bg-surface-white`, 여백)만 `className`으로 넘겨 덮었다.
