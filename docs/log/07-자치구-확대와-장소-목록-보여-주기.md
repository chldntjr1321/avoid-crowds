## 결정과 이유

### 확대는 `viewBox`를 바꿔서 한다

```ts
function getViewBox(gu: string | null): string {
  if (!gu) {
    return SEOUL_VIEW_BOX; // '0 0 1000 1000'
  }
  const targetGu = districts.find((district) => district.name === gu);
  if (!targetGu) {
    return SEOUL_VIEW_BOX;
  }
  const [[left, top], [right, bottom]] = targetGu.bbox;
  const width = right - left;
  const height = bottom - top;
  const pad = Math.max(width, height) * 0.3;

  return `${left - pad} ${top - pad} ${width + pad * 2} ${height + pad * 2}`;
}
```

- `viewBox="x y 너비 높이"`는 "좌표의 이 범위를 화면에 보여 줘"라는 뜻이다. 범위를 고른 자치구 근처로 좁히면 그 범위가 `<svg>` 크기에 맞게 늘어나서 확대된 것처럼 보인다. path 좌표는 하나도 바꾸지 않는다.
- 이 함수는 "얼마나" 확대할지가 아니라 "**어디를**" 보여 줄지 계산한다. 배율 숫자는 코드 어디에도 없다. 범위가 좁은 자치구는 많이, 넓은 자치구는 적게 확대되어 어떤 자치구든 화면에 꽉 찬다.
- 범위는 변환 스크립트가 `districts.json`에 미리 넣어 둔 `bbox`(자치구를 딱 감싸는 네모)를 쓴다. `bbox`는 `[[왼쪽, 위], [오른쪽, 아래]]`이고 `viewBox`는 "왼쪽 위 + 너비·높이"라서 너비 = 오른쪽 − 왼쪽, 높이 = 아래 − 위로 바꾼다.
- `getFillColor`처럼 `gu`만 받아 글자를 돌려주는 함수라 컴포넌트 밖에 두었다. 서울 전체 범위 `'0 0 1000 1000'`은 `SEOUL_VIEW_BOX` 상수로 이름을 붙였다.
- `if (!gu)`를 `find`보다 먼저 두었다. 25개 `find`는 성능 차이가 없지만, "골랐나 → 찾기 → 계산" 순서로 읽혀서 `getValidMapQuery`와 같은 흐름이 된다.

### 여백은 자치구 크기에 비례, 긴 쪽 기준 30%

- `bbox`를 그대로 쓰면 자치구가 화면 끝에 붙는다. 네모를 사방으로 `pad`만큼 넓혔다. 왼쪽 x와 위쪽 y는 빼고, 너비와 높이는 **`pad × 2`** 를 더한다. 한 번만 더하면 한쪽만 넓어져서 가운데에서 벗어난다.
- 고정 숫자로 하면 작은 중구에서는 여백이 너무 크고 큰 강서구에서는 너무 작다. 그래서 자치구 크기에 비례하게 했다.
- 처음에는 너비만 기준으로 했는데, 은평구처럼 세로로 긴 자치구는 위아래 여백이 좁아졌다. 너비와 높이 중 **긴 쪽**(`Math.max`)을 기준으로 바꿨다. 비율 30%는 화면을 보고 정했다.

### `<svg>` 폭에서 패널 자리를 뺀다

- `<svg>`가 `w-full`이면 화면 전체 폭의 가운데에 확대된 자치구가 오는데, 오른쪽 360px를 패널이 덮어서 자치구 오른쪽이 가려졌다.
- 확대 계산을 바꾸지 않고 `<svg>` 폭을 `w-[calc(100%-360px)]`로 줄였다. 360px은 패널의 `right-5`(20px) + `w-85`(340px)다. 이제 "가운데"가 패널 왼쪽의 보이는 영역 가운데다. 서울 전체 화면의 지도도 같이 왼쪽으로 옮겨져서 원래 가려지던 부분이 보인다.
- Tailwind 대괄호 안에는 띄어쓰기를 넣으면 안 된다. Tailwind가 띄어쓰기를 클래스 구분으로 읽는다.
- 모바일에서는 패널이 바텀시트가 되어 이 값이 맞지 않는다. 모바일 작업 때 다시 본다.

### 고른 자치구는 `map`에서 빼고 맨 마지막에 따로 그린다

- SVG에는 `z-index`가 없고 **코드에 적힌 순서대로** 그려서 뒤의 요소가 앞을 덮는다. 맞닿은 경계선은 두 자치구가 각자 한 번씩 그려서, 나중에 그린 자치구의 선 색이 보인다.
- 처음에는 `districts.json` 순서대로 그렸더니 은평구(11번)를 골랐을 때 서대문구(12번)·마포구(13번) 쪽 경계는 그 자치구들의 연한 선에 덮여 연하게, 종로구(0번) 쪽 경계는 진하게 보였다. 고른 자치구에 따라 결과가 달랐다.
- `map` 콜백에서 고른 자치구면 `null`을 돌려줘 건너뛰고(React는 `null` 자리에 아무것도 그리지 않는다), `map`이 끝난 다음 `selectedGu && <path ... />`로 따로 그렸다. 배열 순서를 바꿔 고른 자치구를 맨 뒤로 보내는 방법도 있었지만, 그 바로 다음에 장소를 그려야 해서 따로 그리는 쪽이 코드를 붙이기 쉬웠다.

### 나머지 자치구는 옅게, 누르면 서울 전체로

| 상태               | 조건                        | 색                                             | 누르면                                |
| ------------------ | --------------------------- | ---------------------------------------------- | ------------------------------------- |
| 서울 전체의 자치구 | `gu` 없음                   | 혼잡도 색                                      | 그 자치구로 (장소 없는 자치구는 막음) |
| 고른 자치구        | `gu === district.name`      | 혼잡도 색                                      | 아무 일 없음                          |
| 옅어진 자치구      | `gu` 있음, 고른 자치구 아님 | `fill-map-outside` + `stroke-map-outside-line` | 서울 전체로                           |

- 변수는 `isSelected` → `isFaded` → `isClickable` 순서로, 앞의 값을 써서 다음 값을 만든다.
- 옅은 색 결정은 `getFillColor` **밖**에서 나눴다. `getFillColor`는 "혼잡도 → 색"만 하는 함수로 둔다.
- 고른 자치구에 `onClick`을 달지 않은 이유: 이미 `/?gu=중구`인데 중구를 또 누르면 같은 주소가 `push`돼 기록이 한 칸 쌓이고, 뒤로 가기를 두 번 눌러야 서울 전체로 돌아간다.
- 옅은 자치구 클릭은 원래 11/9 이후 "돌아가기" 항목이다. 확대한 뒤 돌아갈 방법이 브라우저 뒤로 가기밖에 없어서 앞당겼다. 코드가 [← 서울 전체] 버튼과 같은 "서울 전체 주소로 이동"이라 부담이 작았다.
- `router.back()`이 아니라 `push('/')`인 이유: `/?gu=중구` 링크로 바로 들어온 사람이 뒤로 가면 우리 사이트를 나가 버린다. `push`는 어떻게 들어왔든 서울 전체로 간다.
- 옅어진 중랑구(장소 없음)도 누를 수 있게 했다: `isClickable = Boolean(guLevels?.[district.name] || isFaded)`. 확대 화면에서는 옅은 자치구가 모두 같은 색이라 사용자는 중랑구가 데이터 없는 자치구라는 걸 볼 수 없다. 다른 옅은 자치구는 눌리는데 중랑구만 안 눌리면 고장 난 것처럼 보인다. 그리고 옅은 자치구를 누르는 건 "그 자치구로 간다"가 아니라 "서울 전체로 돌아간다"라서 데이터 유무와 상관없다. `'중랑구'`를 직접 적지 않고 데이터로 판단해서, 데이터 없는 자치구가 바뀌어도 그대로 맞는다.

### 확대하면 선도 같이 굵어지게 둔다

- `strokeWidth`는 viewBox **좌표 단위**라서 6배 확대하면 선도 6배 굵어진다. `vectorEffect="non-scaling-stroke"`를 주면 화면 픽셀 기준 두께로 고정된다.
- "가까이 들여다본다"는 확대 의도에는 선도 같이 커지는 게 맞다고 보고 쓰지 않았다. 도안의 확대 화면은 선이 얇은 편이라, 나중에 비교해 보고 다시 정할 수 있다.
- 가장자리로 갈수록 바탕색으로 사라지는 효과(radialGradient)는 11/9 이후 지도 꾸밈으로 미뤘다. viewBox가 자치구마다 바뀌어서 SVG gradient로 하면 위치를 매번 다시 계산해야 한다. 할 때는 `<svg>` 요소에 CSS `mask-image: radial-gradient(...)`를 거는 방법을 먼저 시도해 본다(화면 기준이라 viewBox와 상관없다).

### 장소 모양은 `places.json`, 장소 색은 `/api/places`, `code`로 짝짓는다

```tsx
const selectedGuPlaces = placeList.filter((p) => p.guName === gu);

{
  selectedGuPlaces.map((p) => {
    const targetPlace = data?.find((d) => d.code === p.code);
    return (
      <path
        key={p.code}
        d={p.d}
        className={cn(
          targetPlace ? LEVEL_COLOR[targetPlace.level] : 'fill-congestion-none',
          'stroke-map-line',
        )}
      />
    );
  });
}
```

- 모양(`d`)은 지도 데이터 `placeList`에, 혼잡도 단계는 API 데이터 `data`에 있다. 장소마다 `code`로 `data`에서 찾아 짝짓는다.
- `filter`는 조건에 맞는 것을 **전부** 모은다. 서울 전체 화면에서는 `gu`가 `null`이라 빈 배열이 되고, 빈 배열의 `map`은 아무것도 그리지 않아서 `selectedGu &&`로 감쌀 필요가 없다.
- 데이터가 아직 없거나 그 장소만 서울시에서 실패해 빠졌으면 회색(`fill-congestion-none`)으로라도 **모양은 그린다.** early return으로 건너뛰면 장소가 사라져서 "여기 장소가 있는데 데이터가 없다"를 알 수 없다.
- 장소는 단계를 직접 갖고 있어서 자치구용 `getFillColor`(자치구별 단계 표에서 찾는 함수)가 아니라 `LEVEL_COLOR[단계]`를 바로 쓴다.
- 변수 이름은 `places` 대신 `selectedGuPlaces`로 했다. 이 파일에 `placeList`, `data`처럼 장소 관련 이름이 여럿 있어서 "고른 자치구의 장소"라는 게 보이는 이름이 낫다.

### 자치구 밖으로 나간 장소는 `clipPath`로 자른다

- 서울시 장소 영역은 자치구 경계와 상관없이 그려져서, 경계에 걸친 장소는 옆 자치구로 삐져나온다. `03` 문서에도 "구 경계 밖은 `<clipPath>`로 자른다"고 되어 있다.
- `<defs>` 안 `<clipPath id="selected-gu-clip">`에 고른 자치구 path를 넣어 "자를 모양"으로 등록하고, 장소들을 `<g clipPath="url(#selected-gu-clip)">`로 한 번에 감쌌다.

### 장소에 덮인 자치구 경계선은 맨 위에 다시 그린다

- 선(stroke)은 path 경계를 가운데에 두고 안쪽 절반, 바깥쪽 절반으로 그려진다. 장소가 자치구 위에 그려지면서 자치구 경계선의 안쪽 절반을 덮고, 장소 자신의 선은 clipPath에 잘려 안쪽 절반만 남는다. 그래서 장소와 맞닿은 경계만 얇아 보였다.
- 장소를 다 그린 다음 고른 자치구의 **선만**(`fill="none"`) 한 번 더 그렸다. 면을 칠하면 장소를 다 덮는다.

### 장소 목록은 `/api/places` 데이터로, 컴포넌트를 나눈다

- 목록에는 이름과 혼잡도가 필요해서 이번에는 `placeList`가 아니라 `data`를 `guName`으로 거른다.
- `FloatingPanel`은 "무엇을 보여 줄지 고르기", 새 컴포넌트 `PlaceList`(`panel/place-list.tsx`)는 "목록 그리기"를 맡는다. `PlaceList`는 `places: Place[]` 하나만 받는다. `code`, `name`, `level`은 각 `Place`에 이미 들어 있다.
- 항목을 나열하는 거라 `<ul>`/`<li>`를 썼다. 스크린리더가 "목록, 항목 10개"처럼 읽는다.
- `data`가 없을 때 early return하지 않는다. 그때도 "불러오는 중"과 실패 안내를 보여 줘야 한다. 거르는 코드를 `if (data)` 블록 **안**에 두면 TypeScript가 `data`를 `Place[]`로 알아준다.
- 패널 본문 변수 이름을 `message`에서 `content`로 바꿨다. 처음에는 상태 안내 문구만 담았지만 이제 목록, 나중에는 TOP 5와 장소 상세까지 담는다.
- 도안의 요약 줄, 정렬 탭, 인구 범위, 색 뱃지는 11/9 이후다. MVP는 이름과 단계 글자만.

### 정렬은 `sortByMostCrowded`, 원본은 건드리지 않는다

```ts
export function sortByMostCrowded(places: Place[]): Place[] {
  return [...places].sort((a, b) => {
    const scoreA = levelToScore(a.level);
    const scoreB = levelToScore(b.level);

    return scoreB - scoreA
      ? scoreB - scoreA
      : b.population.max - a.population.max;
  });
}
```

- 붐빔 → 여유 순, 단계가 같으면 인구가 많은 순이다(`03` 문서의 TOP 5 규칙과 같다).
- 단계 글자끼리는 크기를 비교할 수 없어서 기존 `levelToScore`(여유 1 ~ 붐빔 4)로 바꿔 비교한다. 점수 배열을 `map`으로 먼저 만들면 점수가 어느 장소 것인지 사라지므로, `sort` 콜백 **안에서** 비교하는 순간 바꾼다.
- 콜백 하나가 "누가 앞인가"를 끝까지 정해야 해서, 점수 차가 0(falsy)이면 인구 비교로 넘어간다.
- `sort`는 **원래 배열을 직접 바꾼다.** `data`는 TanStack Query 캐시에 저장된 배열이라, 나중에 TOP 5에서 `data`를 그대로 넘기면 지도 쪽 데이터 순서까지 바뀐다. 그래서 함수 안에서 `[...places]`로 복사한 뒤 정렬해, 어디서 불러도 넘긴 배열이 바뀌지 않게 했다. 대신 **돌려받은 값을 써야** 한다.
- TOP 5에서도 쓰려고 `congestion.ts`에 두었다. 이름은 방향까지 드러나게 `sortByMostCrowded`로 했다. 나중에 한적 탭이 생기면 `sortByLeastCrowded`와 짝이 된다.

### [← 서울 전체]는 도안과 달리 패널 맨 위에

- 도안(`02-district`)은 지도 왼쪽 위인데, 장소 상세 도안(`03-place`)의 [← 중구 장소 목록] 버튼은 패널 맨 위에 있다. 두 화면의 "뒤로 가기" 자리를 맞추려고 패널 맨 위로 옮겼다. 사용자는 "돌아가려면 패널 위를 본다"만 기억하면 된다.
- 모양도 `03-place`의 버튼 값을 그대로 썼다: `variant="outline"` + `self-start rounded-sm border-input bg-surface-white px-2.5 py-1.5 text-[13px]`. `self-start`는 `flex-col`인 패널 안에서 버튼이 폭을 꽉 채우지 않고 글자 길이만큼만 차지하게 한다.
- 화면을 바꾸는 링크라 `router.push` 대신 `next/link`의 `<Link>`를 썼다. 진짜 `<a>`라서 새 탭 열기, 가운데 클릭도 된다. `<Link>`도 기본이 `push`라서 뒤로 가기로 돌아온다.
- `<Button>` 안에 `<Link>`를 넣으면 `<button><a>…</a></button>`처럼 누를 수 있는 요소가 겹친다. shadcn Button의 **`asChild`** 로 `<a>` 하나만 남겼다.
- 주소는 `getMapHref({ gu: null, place: null })` 대신 `href="/"`를 직접 적었다. 결과는 같다.

### 장소 클릭: 지도는 `router.push`, 목록은 `<Link>`

- 지도의 장소 path에 `onClick={() => router.push(getMapHref({ gu, place: p.code }))}`를 달았다. 코드는 API 데이터(`targetPlace`)가 아니라 지도 데이터 `p.code`에서 가져온다. 데이터가 없어도 클릭이 동작한다.
- `03` 문서의 "목록 클릭 = 지도에서 장소 클릭과 같음"에 따라 `PlaceList`의 각 줄을 `<Link>`로 감쌌다. `<ul>` 바로 아래에는 `<li>`만 올 수 있어서 `<li>` 안에 `<Link>`를 넣는다. `PlaceList` 안에는 `gu` 변수가 없어서 각 장소의 `p.guName`으로 주소를 만든다.
- 서울대공원 클릭은 장소 상세를 만든 뒤로 미뤘다.

## 문제와 해결

### `bbox`에서 꺼낸 변수 이름이 실제 값과 달라 위치가 틀림

- **원인**: `const [[x, up], [y, down]] = bbox`로 꺼냈는데, `y` 자리에 실제로 들어가는 값은 **오른쪽**이다. 그 `y`를 viewBox 두 번째 자리(위쪽)에 써서 중구일 때 `'469.8 625.7 …'`처럼 중구보다 아래쪽을 보여 줬다. 너비·높이는 우연히 맞았다.
- **해결**: 이름을 뜻 그대로 `left`, `top`, `right`, `bottom`으로 바꿨다. 그러자 다음에 `${left} ${right} …`로 잘못 쓴 줄도 바로 눈에 보였다. 이름을 뜻대로 지으면 이런 실수가 드러난다.
- 이때 `targetGu?.bbox`를 구조 분해하려다 `'number[][] | undefined' 형식에는 ... '[Symbol.iterator]()' 메서드가 있어야 합니다` 오류도 났다. `find`가 못 찾으면 `undefined`이고, `undefined`에서는 칸을 꺼낼 수 없다는 뜻이다. 못 찾으면 먼저 `return`해서 해결했다.

### `&&`가 참/거짓이 아니라 값을 그대로 돌려줌 (두 번)

- `const isFaded = gu && !isSelected`: `gu`가 `null`이면 `false`가 아니라 `null`이 담겼다. `Boolean(gu && !isSelected)`로 감쌌다.
- 중랑구 클릭을 고치려고 `href`에 `&&`를 넣었다가 다른 자치구에서 `href`가 `false`가 되어 `Argument of type 'string | false' ...` 오류가 났다. 막고 있던 건 `href`(어디로 가나)가 아니라 `isClickable`(누를 수 있나)이었다. `href`는 되돌리고 `isClickable`을 고쳤다.

### 컴포넌트와 `map` 콜백이 아무것도 돌려주지 않음

- **원인**: `PlaceList`를 처음 만들 때 함수 본문에 JSX를 적기만 하고 `return`하지 않았다. `map` 콜백도 마찬가지라 `Type 'void[]' is not assignable to type 'ReactNode'` 오류가 났다.
- **해결**: 둘 다 `return`을 넣었다. 같은 시기에 props를 `({ places }: PlaceListProps)`가 아니라 배열로 직접 받으려던 실수도 함께 고쳤다(React 컴포넌트는 props 객체 하나를 받는다).

### 목록의 이름과 단계가 양쪽 끝으로 안 벌어짐

- **원인 1**: `<li>` 안이 `{p.name} {p.level}`처럼 글자뿐이었다. 이어진 글자는 브라우저가 한 덩어리로 묶어서 flex가 벌릴 요소가 없다. 각각 `<span>`으로 감쌌다.
- **원인 2**: `<ul>`이 flex인 부모 `div` 안에서 글자 길이만큼만 폭을 가졌다. `<ul>`에 `flex-1`을 줘서 남은 폭을 다 차지하게 했다.
- 나중에 `<li>` 안을 `<Link>`로 감싸면서 이름과 단계가 `<Link>`의 자식이 되어 다시 안 벌어졌다. `flex justify-between`을 `<Link>`로 옮겼다. flex는 **바로 아래 자식**에만 영향을 준다.

### 정렬 결과를 버리거나 두 번 정렬함

- `sortByMostCrowded`는 복사본을 돌려주므로 `sortByMostCrowded(selectedGuPlaces);`만 쓰면 결과가 버려진다. 변수에 담았는데, 이번에는 담은 결과를 또 `sortByMostCrowded(...)`로 감싸 넘겨서 두 번 정렬했다. 변수 하나(`sortedGuPlaces`)만 넘기는 걸로 정리했다. "거르기 → 정렬 → 넘기기"가 한 줄에 하나씩 읽힌다.
- 정렬 초안에서는 삼항 연산자의 참/거짓 자리가 반대라 여유가 앞에 오고, 함수가 결과를 `return`하지 않았다. 예시 데이터로 실행해서 순서를 확인하고 고쳤다.

## 확인한 사실

- 중구 `bbox`는 `[[469.8, 480.2], [625.7, 564.3]]`, 너비 약 155.8이라 여백 없이 약 6.4배 확대된다. 실제 배율은 `<svg>` 기본값 `preserveAspectRatio="xMidYMid meet"`(비율 유지, 다 들어가게, 가운데 정렬) 때문에 너비와 높이 중 더 많이 줄여야 하는 쪽에 맞춰진다.
- 데이터를 받은 시간대(새벽~낮)에는 대부분 장소가 '여유'라서 장소 색이 거의 같은 초록이었다.
- 정렬 함수를 예시 데이터 `A(여유,100) B(붐빔,10) C(여유,500) D(보통,50)`로 실행하면 `B D C A`가 되고, 원본 배열 순서는 그대로다.
- 장소를 누르면 `/?gu=중구&place=POI...`로 바뀌고, 뒤로 가기로 `/?gu=중구`에 돌아온다. 이 시점에는 패널 내용이 아직 바뀌지 않는다(로그 08).

## 새로 배운 것

### `viewBox`

- `viewBox="x y 너비 높이"`는 `<svg>` 안 좌표 중 어느 범위를 보여 줄지 정한다. `<svg>`가 화면에서 차지하는 크기(`className`)는 그대로 두고 범위만 바꾸면 확대·축소가 된다.
- 선 두께(`strokeWidth`)도 이 좌표 단위라서 범위를 좁히면 선도 굵어진다. `vectorEffect="non-scaling-stroke"`는 두께를 화면 픽셀 기준으로 바꾼다(React에서는 camelCase).

### SVG의 그리기 순서와 선

- SVG에는 `z-index`가 없다. 코드에 적힌 순서대로 그려서 나중 요소가 위에 온다. 위에 보여야 하는 것은 나중에 그린다.
- 선은 path 경계를 가운데에 두고 안쪽 절반, 바깥쪽 절반으로 그려진다. 그래서 위에 그린 면이 아래 선의 절반을 덮을 수 있다.

### `clipPath`, `<defs>`, `<g>`

- `<defs>` 안의 요소는 그려지지 않고 정의만 된다.
- `<clipPath id="이름">` 안의 모양은 "자를 모양"이다. 다른 요소에 `clipPath="url(#이름)"`를 붙이면 그 모양 **안쪽**만 보인다. `id`는 페이지에서 하나뿐이어야 하고, `#` 뒤 글자가 하나라도 다르면 틀을 못 찾아 아무것도 안 잘린다.
- `<g>`는 여러 요소를 묶는 태그다. `<g>`에 `clipPath`를 붙이면 안의 요소가 모두 같은 틀로 잘린다.

### `&&`와 `||`는 값을 그대로 돌려준다

- `A && B`: A가 falsy면 **A 그대로**, 아니면 B. `null && x`는 `false`가 아니라 `null`이다.
- `A || B`: A가 truthy면 **A 그대로**, 아니면 B. `'여유' || x`는 `'여유'`다.
- 그래서 `is...` 변수처럼 참/거짓이 필요하면 `Boolean(...)`으로 감싼다.

### `sort`는 원본을 바꾼다

- `a.sort()`는 `a` 자체를 바꾸고, 돌려주는 것도 새 배열이 아니라 `a` 그대로다(`a.sort() === a`).
- 원본을 지키려면 `[...a].sort(...)`처럼 복사한 뒤 정렬하거나 `a.toSorted(...)`(새 배열을 돌려줌)를 쓴다.
- 비교 함수가 음수를 돌려주면 `a`가 앞, 양수면 `b`가 앞이다. 큰 것을 앞에 두려면 `b − a`.

### `flex`와 `flex-1`은 다른 일을 한다

| 클래스   | CSS             | 영향                                                      |
| -------- | --------------- | --------------------------------------------------------- |
| `flex`   | `display: flex` | **내 자식들**을 flex로 배치                               |
| `flex-1` | `flex: 1 1 0%`  | **나 자신**이 부모 안 남은 공간 차지 (부모가 flex일 때만) |

- `flex-1`을 붙여도 그 요소가 flex 상자가 되지는 않는다. `ErrorState`처럼 둘 다 필요한 요소에는 둘 다 붙인다.

### shadcn `Button`의 `asChild`

- `button.tsx`는 `const Comp = asChild ? Slot.Root : "button"`이다. `asChild`가 있으면 radix-ui의 `Slot`이 자기 태그를 만들지 않고, 버튼 모양 클래스와 props를 **바로 아래 자식 하나**에 붙인다.
- `<Button asChild><Link href="/">…</Link></Button>` → `<a href="/" class="버튼 모양">…</a>`. 보이는 건 버튼, 실제로는 링크다.
- 자식은 요소 하나여야 해서 아이콘과 글자는 `<Link>` 안에 넣는다. `variant`, `className`은 `<Button>`에, `href`는 `<Link>`에 준다.

### `map` 콜백에서 `null`을 돌려주면 그 자리는 그려지지 않는다

- `districts.map`에서 고른 자치구일 때 `return null`로 건너뛰었다. 빈 배열의 `map`도 아무것도 그리지 않는다.
