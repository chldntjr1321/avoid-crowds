## 결정과 이유

### 화면 상태는 `useState`가 아니라 주소에 둔다

- `03` 문서 1절에서 정한 규칙이다. "지금 어느 자치구를 보고 있나"를 주소에서 그때그때 읽으면 새로고침, 링크 공유, 뒤로 가기가 모두 저절로 맞는다. 뒤로 가기를 누르면 주소가 바뀌고, 주소가 바뀌면 다시 읽기 때문이다.
- 새로고침해도 쿼리스트링이 남는 건 우리가 저장해서가 아니라 브라우저가 "지금 주소창의 주소를 다시 여는" 동작이라서다. 페이지가 다시 열리면 `useMapQuery`가 처음부터 주소를 읽고 검사한다. `useState`에 담았다면 새로고침할 때 사라졌을 것이다.

### 주소는 훅 하나(`useMapQuery`)로 읽는다

- 주소 값은 `SeoulMap`(어느 자치구를 확대할지)과 `FloatingPanel`(무엇을 보여 줄지) **둘 다** 필요하다. 그래서 어제 `usePlaces`처럼 훅 하나로 만들어 두 컴포넌트가 각자 부른다.
- 다른 방법으로 `page.tsx`(서버 컴포넌트)의 `searchParams` prop으로 받아 내려 줄 수도 있었다. 하지만 두 컴포넌트가 이미 클라이언트 컴포넌트이고, `usePlaces`와 같은 방식이 설명하기 쉬워서 훅을 골랐다.
- 훅 파일에는 `'use client'`가 없다. 클라이언트 컴포넌트가 import해서 쓰면 클라이언트 쪽에서 돈다.
- `useSearchParams`는 `next/navigation`에서 가져온다. `next/router`는 옛 Pages Router용이다.

### `SeoulMap`과 `FloatingPanel`을 `<Suspense>`로 감쌌다

```tsx
// page.tsx
<main className="relative h-screen bg-background">
  <Suspense fallback={null}>
    <SeoulMap />
    <FloatingPanel />
  </Suspense>
</main>
```

- 이 페이지는 `pnpm build` 때 미리 HTML로 만들어진다(prerender, 결과 `○ Static`). 그런데 빌드할 때는 누가 `/?gu=중구`로 들어올지 알 수 없다. 그래서 `useSearchParams`는 빌드 중에 **일부러 렌더링을 멈추고(suspend)**, React가 가장 가까운 `<Suspense>`를 찾아 그 안쪽을 fallback으로 채운다. 바깥(`<main>`)은 미리 만든 HTML로 보내고, 안쪽은 브라우저에서 실제 주소로 그린다.
- 감싸지 않으면 Cache Components가 켜진 상태에서 빌드가 실패한다. 직접 빼고 빌드해서 확인했다(아래 "확인한 사실").
- 오류 문구가 알려 준 다른 해결법 `export const instant = false`는 "이 페이지는 미리 만들지 말고 요청마다 기다렸다 그려도 된다"는 허락이다. Static의 장점(빌드 때 만든 HTML을 바로 보내기)이 없어져서 고르지 않았다.
- fallback은 `null`이다. 처음 받은 HTML의 `<main>` 안은 비어 있고, JS가 실행된 뒤 지도와 패널이 그려진다. 빈 순간이 아주 짧아서 MVP에는 충분하다. 로딩 화면(1-L)을 다듬을 때 fallback에 빈 지도 모양을 넣을지 다시 본다.
- 이 Suspense는 **데이터 로딩용이 아니다.** 주소 때문에 빌드 중에 멈추는 것만 받아 준다. 혼잡도 데이터가 아직 안 온 상태는 `useQuery`의 `data: undefined`와 컴포넌트 안의 분기(지도는 `fill-map-empty`, 패널은 "불러오는 중")가 처리한다.

### 주소 검사는 `/api/places` 응답이 아니라 `src/data/generated/`의 JSON으로 한다

- `usePlaces()`의 `data`는 응답이 오기 전에는 `undefined`이고, 요청이 실패하면 **계속** `undefined`다. 이걸 기준으로 검사하면 데이터가 오기 전에는 모든 자치구가 "틀린 자치구"가 된다. 그 상태에서 "틀리면 `router.replace`로 지운다"를 붙이면 **맞는 주소가 지워진다.**
- `districts.json`(25개 자치구 `name`)과 `places.json`(121곳의 `code`, `guName`)은 변환 스크립트(`pnpm build:map`)로 미리 만들어 둔 파일이다. import하면 번들에 그대로 들어가서 화면이 처음 그려질 때부터 값이 있다. 기다릴 것도 실패할 일도 없다.
- "중구라는 자치구가 있나", "POI091이 중구 소속인가"는 5분마다 바뀌는 혼잡도와 달리 **변하지 않는 정보**다. 변하지 않는 정보는 변하지 않는 파일로 확인하는 게 맞다.

### 검사는 `lib/`의 순수 함수로, 부르는 건 훅 안에서

- 검사 로직은 `lib/map-query.ts`의 `getValidMapQuery`에 두었다. 훅을 쓰지 않고 인자만 받으니 컴포넌트 밖에 둘 수 있고, 따로 실행해 확인하기도 쉽다. 어제 `getFillColor`를 컴포넌트 밖으로 뺀 것과 같은 이유다.
- 컴포넌트가 주소 읽기와 검사를 각각 부르지 않는다. `useMapQuery`가 안에서 검사까지 해서 **검사된 값만** 내보낸다. 그래서 컴포넌트가 검사를 깜빡하고 `'장귤'`을 쓰는 일이 생기지 않는다.
- 자치구 이름 목록은 `new Set(...)`으로 **함수 밖에서 한 번만** 만든다. 함수 안에 두면 부를 때마다 새로 만든다.

### 검사 규칙: 걸러낼 경우를 먼저 `return`한다 (early return)

```ts
export function getValidMapQuery({ gu, place }: MapQuery): MapQuery {
  // 자치구 이름이 없거나 목록에 없을 때
  if (!gu || !guNames.has(gu)) {
    return { gu: null, place: null };
  }
  // 장소 코드가 없거나 그 자치구 소속이 아닐 때
  const isValidPlaceCode = placeList.some(
    (p) => p.code === place && p.guName === gu,
  );
  if (!isValidPlaceCode) {
    return { gu, place: null };
  }

  return { gu, place };
}
```

| 순서 | 걸러낼 조건                                     | 돌려줄 값                       |
| ---- | ----------------------------------------------- | ------------------------------- |
| ①    | 자치구가 없거나 목록에 없음                     | `gu`, `place` 둘 다 `null`      |
| ②    | 장소 코드가 목록에 없거나 그 자치구 소속이 아님 | `gu`는 그대로, `place`만 `null` |
| 끝   | 둘 다 통과                                      | 받은 그대로                     |

- `03` 문서 6절의 규칙(자치구가 틀리면 서울 전체, 장소만 틀리면 그 자치구까지만)을 그대로 옮겼다.
- ①이 먼저여야 한다. ②는 "장소의 `guName`이 주소의 `gu`와 같은가"를 보는데, `gu`가 맞는 자치구라는 게 확인된 뒤에 봐야 의미가 있다. ①에서 `!gu`로 걸러 두면 아래에서 TypeScript도 `gu`를 `string`으로 알아준다(narrowing).
- `if` 안에 `if`가 겹치지 않아서 위에서 아래로 읽으면 규칙 표가 그대로 보인다.
- `place`가 아예 없는 경우(`/?gu=중구`)를 위한 `if`는 따로 없다. `place`가 `null`이면 `some`이 `false`를 돌려줘서 ②에 걸리고 `{ gu: '중구', place: null }`이 된다. 원래 값과 같다.

### `gu` 없이 `place`만 온 주소는 서울 전체로 보낸다

- `/?place=POI091`처럼 자치구 없이 장소만 오면 ①에 걸려 서울 전체가 된다. "장소는 자치구 안에서만 고른다"는 흐름이 단순해진다.
- 장소의 `guName`으로 `gu`를 채워 주는 방법도 있었지만 규칙이 하나 늘어서 고르지 않았다.
- 서울대공원(`POI100`, `guName: '과천시'`)은 `districts.json`에 과천시가 없어서 지금 규칙으로는 틀린 주소다. 서울대공원은 클릭하면 바로 장소 상세로 가니까, 주소 모양은 장소 상세를 만들 때 정하기로 했다(11/9에 `?place=POI100`으로 정했다. 로그 10 참고).

### `find` 대신 `some`

- 처음에는 `placeList.find(...)`의 결과를 `isValidPlaceCode`에 담았다. 그런데 `is`로 시작하는 이름은 `true`/`false`를 기대하게 하고, `find`는 **찾은 장소 객체나 `undefined`** 를 돌려준다. 이름과 값이 달랐다.
- 여기서는 찾은 객체를 쓰지 않고 "있나?"만 본다. 그래서 조건에 맞는 게 하나라도 있으면 `true`를 돌려주는 `some`으로 바꿨다. 이름, 메서드, 하는 일이 모두 맞는다.

### 이름: `getValidMapQuery`, 파일은 `lib/map-query.ts`

- `check`, `is`, `has`로 시작하는 함수는 보통 참/거짓을 돌려준다. 이 함수는 **검사를 통과한 `{ gu, place }` 객체**를 돌려주니까 값을 얻는다는 뜻의 `get`이 맞다(`congestion.ts`의 `getGuLevels`와 같은 방식).
- 이 프로젝트에서 "query"는 두 가지 뜻으로 쓰인다. 주소의 **쿼리스트링**(`?` 뒤의 `gu=중구&place=POI091`)과 **TanStack Query**(서버 데이터를 조회하는 요청 하나, `useQuery`·`queryKey`)다. `useMapQuery`, `getValidMapQuery`, `MapQuery`의 query는 모두 쿼리스트링 뜻이다. 그래서 파일도 훅 `use-map-query.ts`와 짝을 맞춰 `lib/map-query.ts`로 두었다.

### 인자는 객체 하나로 받는다

- `getValidMapQuery(gu, place)`처럼 따로 받을 수도 있다. 그런데 `gu`와 `place`가 **둘 다 `string | null`** 이라서 `getValidMapQuery(place, gu)`로 순서를 바꿔 넣어도 TypeScript가 잡아 주지 못한다. 실행하면 장소 코드를 자치구 이름으로 검사해서 항상 서울 전체가 나오는데, 원인을 찾기 어렵다.
- 객체로 받으면 이름으로 짝을 짓기 때문에 순서가 상관없다.
- 기준: 인자가 1~2개이고 타입이 서로 다르면 위치 인자(`getFillColor(guLevels, guName)`처럼, 순서를 바꾸면 타입 오류가 난다), 같은 타입이 여러 개이거나 3개 이상이면 객체.

### 잘못된 주소는 `push`가 아니라 `replace`로 고친다

- `router.push`는 브라우저 기록에 **새 칸을 추가**하고, `router.replace`는 **지금 칸을 바꾼다.**
- `push`를 쓰면 기록이 `[?gu=장귤] → [/]`가 된다. 뒤로 가기를 누르면 `?gu=장귤`로 돌아갔다가 다시 `/`로 바뀌어서, 사용자는 뒤로 갈 수 없게 된다. `replace`는 `?gu=장귤` 칸 자체를 `/`로 바꿔서 이 문제가 없다.
- 반대로 서울 전체 → 자치구는 사용자가 한 단계 **들어간** 것이라 `push`로 기록을 남긴다. 그래야 뒤로 가기로 서울 전체에 돌아갈 수 있다.
- Next `useRouter` 문서에 "검사하지 않은 URL을 `push`/`replace`에 넣지 말라(XSS 위험)"는 주의가 있다. 우리는 검사를 통과한 값으로만 주소를 만든다.

### `router.replace`는 `useEffect` 안에서 부른다

```ts
const isInvalid = gu !== validQuery.gu || place !== validQuery.place;

useEffect(() => {
  if (!isInvalid) {
    return;
  }

  const href = getMapHref({ gu: validQuery.gu, place: validQuery.place });

  router.replace(href);
}, [isInvalid, validQuery.gu, validQuery.place, router]);
```

- 날것(`gu`, `place`)과 검사된 것(`validQuery`)을 **둘 다 갖고 있는 곳**이 이 훅뿐이라 여기에 두었다. 둘이 다르면 주소가 잘못된 것이다.
- 컴포넌트(훅) 함수는 "무엇을 그릴지 계산만" 해야 한다. 주소 바꾸기처럼 바깥 세상을 바꾸는 일(부수 효과)을 렌더링 중에 하면, 렌더링 한가운데서 다른 컴포넌트가 다시 그려지는 일이 생겨 React가 경고를 내거나 꼬일 수 있다. `useEffect`는 "화면을 다 그린 다음에 해 줘"라는 뜻이다.
- 훅은 `if` 안에 넣을 수 없다(Rules of Hooks). 그래서 조건은 effect **안**에서 early return으로 처리했다.
- `useMapQuery`를 `SeoulMap`과 `FloatingPanel`이 둘 다 부르면 effect도 두 번 실행돼서 `replace`가 두 번 불린다. 같은 주소로 두 번 바꾸는 거라 화면에 문제가 없어서 MVP에서는 그대로 두었다.

### 의존 배열에 객체가 아니라 글자를 넣는다

- `getMapHref(validQuery)`처럼 객체를 통째로 넘기면 lint가 의존 배열에 `validQuery`를 넣으라고 한다. 그런데 `validQuery`는 `getValidMapQuery`가 렌더링마다 **새로 만드는 객체**다. 의존 배열은 "지난번과 같은 값인가"를 비교하는데, 객체는 내용이 같아도 새로 만들면 다른 것으로 친다. 그러면 effect가 렌더링마다 실행된다.
- 그래서 effect 안에서 `{ gu: validQuery.gu, place: validQuery.place }`로 객체를 **새로 만들어** 넘겼다. effect가 쓰는 값이 `validQuery.gu`, `validQuery.place` 두 글자뿐이라, 실제로 자치구나 장소가 바뀔 때만 다시 실행된다.

### 주소를 만드는 코드는 `getMapHref` 하나로

```ts
export function getMapHref({ gu, place }: MapQuery): string {
  const params = new URLSearchParams();
  if (gu) {
    params.set('gu', gu);
  }
  if (place) {
    params.set('place', place);
  }
  const queryString = params.toString();

  return queryString ? `/?${queryString}` : '/';
}
```

- 처음에는 `useMapQuery`의 effect 안에 있던 코드다. 자치구 클릭(`push`)에서도, 다음 작업의 장소 클릭에서도 같은 일이 필요해서 `lib/map-query.ts`로 꺼냈다. 주소 만드는 규칙이 한곳에만 있으니 바꿀 때도 한 군데만 고치면 된다.
- 이 함수 안에서 `getValidMapQuery`를 **다시 부르지 않는다.** 부르는 두 곳 모두 이미 맞는 값을 넘기기 때문이다. `useMapQuery`는 검사를 마친 `validQuery`를, 자치구 클릭은 `districts.json`에서 온 `district.name`을 넘긴다. 검사는 `getValidMapQuery`, 주소 만들기는 `getMapHref`로 한 함수가 한 가지 일만 한다.
- 돌려주는 건 `gu=...`(쿼리스트링)가 아니라 `/?`까지 붙은 `href`라서 이름을 `getMapHref`로 했다. `href`는 Next 문서의 `router.replace(href: string)` 인자 이름이다.

### 데이터가 없는 자치구는 누를 수 없게 한다

```tsx
const isClickable = Boolean(guLevels?.[district.name]);
const href = getMapHref({ gu: district.name, place: null });

<path
  onClick={isClickable ? () => router.push(href) : undefined}
  className={cn(fillColor, isClickable && 'cursor-pointer', 'stroke-map-line')}
/>;
```

| 상황                           | `guLevels?.[district.name]` | 누를 수 있나 |
| ------------------------------ | --------------------------- | ------------ |
| 데이터 있음 + 장소 있는 자치구 | `'여유'` 등                 | ✅           |
| 데이터 있음 + 중랑구           | `undefined`                 | ❌           |
| 로딩 중·실패                   | `undefined`                 | ❌           |

- 중랑구는 장소가 없어서 들어가도 보여 줄 것이 없다. `03` 문서에도 "hover 안 됨"이라고 되어 있다. 로딩 중·실패 때 막히는 건 덤인데, 1-E(전체 실패)의 "hover 막음"과도 맞는다.
- 이 조건은 클릭과 커서 두 곳에서 쓰여서 변수 하나로 만들었다.
- 핸들러 안에서 `if (!isClickable) return`으로 막는 대신 **핸들러를 아예 주지 않았다**(`onClick={undefined}`는 속성을 안 적은 것과 같다). "누를 수 없는 자치구"라는 뜻이 그대로 드러나고, 나중에 키보드 접근성(`tabIndex`, `role="button"`)을 붙일 때도 "핸들러가 있는 자치구에만"으로 정리하기 쉽다.
- 주소창에 `/?gu=중랑구`를 직접 치는 건 막지 않는다. 중랑구는 실제로 있는 자치구라서 `getValidMapQuery`가 통과시키는 게 맞다. 지도에서 클릭하는 것만 막는다.

### 서울대공원 클릭은 장소 상세를 만들 때

- 서울대공원은 `districts.map`이 아니라 따로 그리는 `<path>`라서 `onClick`이 없다. 클릭하면 바로 장소 상세로 가야 해서, 장소 상세 화면이 먼저 있어야 연결할 수 있다.

## 문제와 해결

### 함수를 부르기만 하고 결과를 버림 (두 번)

- **`find` 결과**: 검사 함수 초안에서 `placeList.find(...)`를 부르기만 하고 변수에 담지 않았다. 마지막 줄은 검사와 상관없이 주소의 `place`를 그대로 돌려줘서 `/?gu=중구&place=POI999`가 그대로 통과했다.
- **`getValidMapQuery` 결과**: `useMapQuery`에서도 `getValidMapQuery({ gu, place })`를 부르고 결과를 담지 않아서, 훅이 날것 `gu`, `place`를 돌려줬다. 패널 제목이 계속 "장귤"로 나왔다.
- **해결**: 결과를 변수(`isValidPlaceCode`, `validQuery`)에 담아 썼다. 함수의 반환값은 받지 않으면 그냥 사라지고, 문법상 틀린 코드가 아니라서 타입 검사도 잡아 주지 않는다.

### `toString()`을 `set` 전에 불러서 항상 빈 주소

- **원인**: `const stringParams = params.toString()`을 `params.set(...)`보다 먼저 썼다. `toString()`은 **부른 순간의 내용을 글자로 찍어 두는 것**이라, 나중에 `params`가 바뀌어도 이미 만든 글자는 그대로다. 그래서 항상 `router.replace('')`가 불렸다.
- **해결**: `new URLSearchParams()` → `set` → `toString()`을 effect 안에서 순서대로 했다(지금은 `getMapHref` 안).

### `params`를 effect 밖에서 만들어 effect가 렌더링마다 실행

- **원인**: `new URLSearchParams()`를 effect 밖에서 만들고 의존 배열에 넣었다. 렌더링마다 새 객체라 매번 "바뀌었다"로 판단됐다.
- **해결**: effect 안에서만 쓰는 값이라 effect 안으로 옮겼다. 의존 배열에서도 빠졌다. lint 경고(`React Hook useEffect has missing dependencies: 'router' and 'stringParams'`)도 이걸로 사라졌다.

### `onClick={router.push()}` → 렌더링하자마자 실행

- **원인**: 괄호가 붙어서 렌더링할 때 `push`를 **실행**하고, 그 결과를 `onClick`에 넘겼다.
- **해결**: `onClick={() => router.push(href)}`처럼 "클릭하면 실행할 함수"를 넘겼다. 어제 `onRetry={() => refetch()}`와 같은 원리다.

## 확인한 사실

- **Suspense 실험** (`useMapQuery`를 `FloatingPanel`에서 부른 상태로 빌드):

  |      | Suspense 있음 | Suspense 없음       |
  | ---- | ------------- | ------------------- |
  | 빌드 | 성공          | 실패                |
  | `/`  | `○ Static`    | 미리 렌더링 중 오류 |
  - 실패 문구: ``Route "/": Next.js encountered URL data `useSearchParams()` in a Client Component outside of `<Suspense>`. This blocks prerendering because the value is only available at runtime.`` 해결법으로 `[stream]` Suspense로 감싸기와 `[block]` `export const instant = false` 두 가지를 알려 준다. `digest: 'CLIENT_HOOK_DYNAMIC'`.
  - Suspense를 넣어도 `○ Static`이 그대로다. 비워 둔 자리는 서버가 요청마다 채우는 게 아니라 브라우저가 채운다. 서버가 보내는 HTML(`<main>`과 fallback `null`)은 모든 사용자에게 같아서 빌드 때 한 번 만들어 두면 된다.

- **검사 함수에 9가지 값을 넣어 실행한 결과**:

  | 들어간 값                       | 결과           |
  | ------------------------------- | -------------- |
  | 없음                            | `null, null`   |
  | `중구`                          | `중구, null`   |
  | `장귤`                          | `null, null`   |
  | `''` (`/?gu=`)                  | `null, null`   |
  | `중구` + `POI002` (중구 소속)   | `중구, POI002` |
  | `중구` + `POI999` (없는 코드)   | `중구, null`   |
  | `중구` + `POI001` (강남구 소속) | `중구, null`   |
  | `place`만 있음                  | `null, null`   |
  | `과천시` + `POI100`             | `null, null`   |

- 브라우저: `/?gu=장귤` → `/`, `/?gu=중구&place=POI999` → `/?gu=중구`, `/?gu=중구`는 그대로. 새 탭에서 다른 사이트를 연 뒤 `/?gu=장귤`로 들어가 주소가 바뀐 다음 뒤로 가기를 누르면 그 사이트로 돌아갔다(`replace`라서 기록이 늘지 않음).
- 자치구 클릭 → 주소와 패널 제목이 바뀐다. 뒤로 가기 → `/`, "서울 전체". 앞으로 가기 → 다시 그 자치구. 중랑구는 커서가 화살표 그대로이고 클릭해도 아무 일이 없다.
- 자치구를 클릭해 주소가 바뀌어도 `/api/places` 요청은 새로 나가지 않는다.

## 새로 배운 것

### `useSearchParams().get()`이 돌려주는 값

- `/?gu=중구` → `'중구'`, `gu`가 없으면 `null`, `/?gu=` → `''`(빈 글자). 그래서 타입이 `string | null`이다.
- 한글이 `%EC%A4%91...`처럼 인코딩돼 있어도 `get()`이 풀어서 돌려준다.
- 돌려받는 객체는 읽기 전용 `URLSearchParams`다.

### suspend와 fallback은 다른 단계다

- **suspend**: 컴포넌트가 "지금은 다 그릴 수 없다"며 렌더링을 멈추는 것. 컴포넌트 쪽에서 일어난다. React 19에서는 `use(아직_안_끝난_Promise)`를 하면 그 자리에서 멈춘다.
- **fallback 보여 주기**: 멈춘 신호를 받은 React가 트리를 위로 올라가 가장 가까운 `<Suspense>`를 찾고, 그 안쪽 **전체** 대신 `fallback`을 그리는 것. Promise가 끝나면 React가 멈췄던 컴포넌트를 처음부터 다시 렌더링한다.
- 이 규칙은 React의 일반 규칙이다. `useSearchParams`만의 특성은 "빌드 중에는 **일부러** 이 규칙을 발동시킨다"는 쪽이다. Next 소스(`navigation.js`의 `useSearchParams` → `dynamic-rendering-client.ts`)를 보면, Cache Components로 미리 렌더링 중일 때(`prerender-client`)는 **영원히 끝나지 않는 Promise**를 `React.use()`에 넘겨 suspend하고, 실제 요청을 처리할 때(`request`)는 그냥 통과해서 값을 바로 돌려준다.
- 그래서 fallback은 "읽는 동안" 보여 주는 게 아니라 "**빌드 때 알 수 없어서 비워 둔 자리**"에 넣어 두는 것이다. 브라우저에서 `get('gu')`는 기다릴 것 없이 바로 나온다.
- `'use client'`는 "브라우저에서만 실행"이 아니라 "브라우저에서**도** 실행"이다. 첫 HTML은 서버(빌드)가 만들기 때문에 클라이언트 컴포넌트도 그때 한 번 실행된다.

### `useQuery`가 처음에 `undefined`를 주는 이유

- React 컴포넌트는 일반 함수처럼 한 번 실행되어 바로 JSX를 돌려줘야 한다. `async`가 아니라서 `await`로 응답을 기다릴 수 없다.
- 그래서 `useQuery`는 기다리지 않고 **지금 캐시 칸(`['places']`)에 있는 값**을 돌려준다. 첫 렌더에는 칸이 비어 있어서 `undefined`, 응답이 오면 칸이 채워지고 TanStack Query가 컴포넌트를 다시 그리게 해서 값이 들어온다. 이미 칸이 차 있으면 첫 렌더부터 `data`가 있고, 갱신 중에는 이전 값을 주면서 뒤에서 새로 불러온다.
- `useSuspenseQuery`는 값이 없으면 `undefined`를 주는 대신 suspend해서 Suspense fallback을 보여 준다. 그러면 `data`가 절대 `undefined`가 아니지만, 데이터가 없을 때 Suspense 안쪽 **전체**(지도 모양까지)가 fallback으로 바뀐다. 우리 도안(1-L, 1-E)은 데이터가 없어도 지도 모양을 보여 주고 색만 비우거나 패널 안내만 바꾸므로, 컴포넌트가 부분별로 처리하는 `useQuery`가 맞다.

### 서버 캐시와 브라우저 캐시, 필터링은 브라우저에서

```
[브라우저]                  [우리 서버 = BFF]                [서울시 서버]
usePlaces()                 /api/places (route.ts)           인구데이터 API
 └ TanStack Query ──GET──▶   └ getPlaces()       ──121번──▶
   (use-places.ts)             'use cache' 5분 캐시
                               인증키 SEOUL_API_KEY
                               toPlace()로 공통 타입 변환
```

- TanStack Query는 API Route가 아니라 **브라우저**에 있다. BFF(우리 화면 전용 중간 서버)는 인증키 숨기기, 121번 호출 모으기, `Place` 타입으로 바꾸기, 서버 캐시를 맡는다.
- 캐시가 두 군데다. **서버 캐시**(`'use cache'`)는 `getPlaces()`의 반환값, 즉 이미 `Place[]`로 가공된 121곳을 저장하고 **모든 사용자**가 같이 쓴다. 서울시 호출 한도를 지키는 역할이다. **브라우저 캐시**(TanStack Query)는 그 JSON을 받아 **그 탭 하나**가 따로 저장한다. 화면을 최신으로 유지하고 컴포넌트 간 중복 요청을 막는 역할이다. 내용은 같지만 서로 다른 복사본이라 시점이 어긋날 수 있다. 서버는 5분이 지난 뒤 첫 요청에 일단 예전 캐시를 주고 뒤에서 갱신하므로, 화면 데이터가 최대 10분 가까이 늦을 수 있다. 화면에 측정 시각(`measuredAt`)을 보여 주는 게 이 차이를 알리는 장치다.
- 쿼리스트링은 요청을 바꾸지 않는다. 페이지 주소는 `/?gu=중구`지만 데이터 요청은 늘 `/api/places`(쿼리스트링 없음)다. 서버는 사용자가 어느 자치구를 보는지 모르고 121곳을 통째로 준다. 고르는 일(중구 장소만 그리기, 자치구별 평균)은 브라우저의 컴포넌트가 렌더링할 때마다 계산한다. 121곳은 한 번에 받아도 크지 않고, 서울 전체 색칠에는 어차피 전부 필요하며, 한 번 받아 두면 자치구를 이리저리 눌러도 요청이 나가지 않는다.
- 자치구마다 따로 요청하는 구조였다면 `queryKey`가 `['places', gu]`처럼 쿼리스트링 값을 포함해야 했을 것이다.

### `||`의 단락 평가와 narrowing

- `||`는 왼쪽이 참이면 오른쪽을 실행하지 않는다(short-circuit). `!gu || !guNames.has(gu)`에서 `gu`가 `null`이나 `''`면 `!gu`에서 끝난다.
- 오른쪽까지 왔다는 건 `gu`가 빈 글자가 아닌 `string`이라는 뜻이라 TypeScript도 오른쪽에서 `gu`를 `string`으로 좁혀 준다. 처음에 `guNames.has(gu)`만 썼을 때 난 `Argument of type 'string | null' ...` 오류가 이걸로 사라졌다.

### Rules of Hooks

- React는 훅을 **부른 순서**로 구분한다. `if` 안에 훅을 두면 렌더링마다 훅 개수가 달라져서 React가 어느 훅이 어느 건지 헷갈린다. 그래서 훅은 항상 함수 맨 바깥에서 매번 같은 순서로 부른다. 어기면 `pnpm lint`(`react-hooks/rules-of-hooks`)가 잡는다.
- 조건이 필요하면 훅 **안**에 넣는다(`useEffect(() => { if (...) return; ... })`).

### `useEffect`와 의존 배열

- `useEffect(() => { ... }, [의존값])`는 "화면을 다 그린 다음에 이 일을 하고, 의존값이 바뀔 때만 다시 해 줘"라는 뜻이다.
- 의존값 비교는 `Object.is`처럼 "같은 값인가"다. 글자·숫자는 내용이 같으면 같지만, 객체는 내용이 같아도 새로 만들면 다르다. 그래서 렌더링마다 만드는 객체를 의존 배열에 넣으면 effect가 매번 실행된다.
- 무엇을 넣을지 모르겠으면 `pnpm lint`(`react-hooks/exhaustive-deps`)가 빠진 값을 알려 준다.

### `URLSearchParams`

- 쿼리스트링을 만들고 읽는 브라우저 내장 객체다. `useSearchParams`가 돌려준 것도 이 객체(읽기 전용판)다.
- `.set(이름, 값)`으로 넣고(같은 이름이 있으면 덮어씀), `.toString()`으로 `?` **없이** 글자를 얻는다. 주소로 쓸 때 `?`는 직접 붙인다.
- `null`을 `set`하면 `gu=null`이라는 글자가 들어가므로, 값이 있을 때만 `set`한다.
