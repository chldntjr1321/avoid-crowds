## 결정과 이유

### 서울대공원 주소는 `?place=POI100` (자치구 없이)

서울대공원(`POI100`)은 서울시 데이터의 121곳 중 유일하게 서울 밖에 있다. `places.json`의 `guName`이 `'과천시'`라서, 지금까지의 "자치구 안에서 장소를 고른다" 규칙에 맞지 않는다.

| 방법  | 주소                      | 결과                                                                                                                                                                  |
| ----- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A     | `?gu=과천시&place=POI100` | 지도는 `gu`가 있으면 나머지 자치구를 전부 옅게 그린다. 과천시는 자치구 목록에 없어서 서울 전체가 회색이 된다. 돌아가기 버튼도 존재하지 않는 "과천시 장소 목록"이 된다 |
| **B** | **`?place=POI100`**       | 지도는 서울 전체 그대로, 패널만 장소 상세로 바뀐다                                                                                                                    |

- B로 정했다. 과천시는 서울 자치구가 아니라서 `gu`를 비워 두는 게 데이터 뜻과도 맞고, 바꿀 곳도 적다. 화면 명세에도 "장소가 1곳뿐이라 클릭하면 바로 장소 상세"로 되어 있다.
- "나중에 경기도를 그리면 `gu`가 생기지 않나?"도 따져 봤다. 데이터 출처가 서울시 API라서 서울 밖 장소는 서울대공원 하나뿐이다. 그런 일이 생기면 그때 과천시 경계를 지도 데이터에 넣고, 허용 지역 목록에 추가하고, 이번 예외를 지우면 된다. 이름도 `gu`보다 `region`이 맞게 되어 어차피 구조를 다시 본다. **지금 필요한 만큼만 만들고 필요해지면 바꾼다.** 면접에서는 "확장 가능성은 고려했지만 데이터 출처상 서울 밖 장소는 하나라서 예외로 처리했다"고 설명한다.

```ts
export const SEOUL_GRAND_PARK_CODE = 'POI100';

export function getValidMapQuery({ gu, place }: MapQuery): MapQuery {
  // 서울대공원은 과천시라 자치구 없이 장소만 있는 주소를 허용
  if (!gu && place === SEOUL_GRAND_PARK_CODE) {
    return { gu: null, place };
  }
  // ...(원래 검사: gu가 없거나 틀리면 둘 다 null 등)
}
```

- 예외는 원래 첫 `if`("`gu`가 없으면 둘 다 `null`") **보다 앞**에 둔다. 뒤에 두면 그 `if`에서 먼저 지워진다.
- `'POI100'`이 `map-query.ts`와 `seoul-map.tsx` 두 곳에서 쓰여서 상수로 만들고 지도에서 가져다 쓴다.
- 이 예외가 왜 있는지는 코드만 봐서는 알 수 없어서 주석을 달았다.

| 주소                      | 결과                                                                |
| ------------------------- | ------------------------------------------------------------------- |
| `?place=POI100`           | 그대로 통과 → 서울대공원 상세                                       |
| `?gu=과천시&place=POI100` | `gu`가 있어서 예외를 건너뛰고, 과천시는 자치구가 아니라서 서울 전체 |
| `?gu=중구&place=POI100`   | 서울대공원은 중구 소속이 아니라서 중구 확대까지만                   |
| `?place=POI046` (용산역)  | 예외에 안 걸리고 `gu`가 없어서 서울 전체                            |

### 서울대공원 화면의 돌아가기 버튼은 "서울 전체"

```tsx
const backLabel = gu && place ? `${gu} 장소 목록` : '서울 전체';

{(gu || place) && (
  <Button …>
```

- 버튼은 원래 `gu`가 있을 때만 나와서 서울대공원 화면에는 없었다. "자치구나 장소 중 하나라도 있으면"으로 바꿨다.
- `backLabel`은 `place`만 보면 서울대공원에서 "null 장소 목록"이 된다. 자치구 장소 목록으로 돌아가는 건 `gu`와 `place`가 **둘 다** 있을 때뿐이다.
- `backHref`는 고치지 않아도 됐다. `gu`가 `null`이면 `getMapHref({ gu: null, place: null })`가 `'/'`를 돌려준다.

| 화면             | 버튼 | 글자           | 이동        |
| ---------------- | ---- | -------------- | ----------- |
| 서울 전체        | 없음 |                |             |
| 중구 확대        | 있음 | 서울 전체      | `/`         |
| 중구의 장소 상세 | 있음 | 중구 장소 목록 | `/?gu=중구` |
| 서울대공원       | 있음 | 서울 전체      | `/`         |

### 고른 장소는 지도 확대 대신 테두리로 표시

- 장소를 고르면 그 장소로 viewBox를 확대하는 방법도 생각했다. 그런데 화면 명세에서 장소 상세의 지도는 자치구 확대 상태 그대로 두고 **고른 장소에 테두리만** 그린다.
- 확대가 필요하다고 느낀 이유는 "어느 장소를 골랐는지 지도에서 안 보여서"였다. 그 문제는 테두리(`--selected`)로 해결되고, 장소마다 viewBox를 다시 계산하는 것보다 훨씬 작은 작업이다.

### 고른 장소 테두리는 경계선 다시 그리기 **뒤**에, 두 조각으로

```tsx
const selectedPlace = selectedGuPlaces.find((p) => p.code === place);

<svg>
  <defs>
    <clipPath id="selected-gu-clip">
      {selectedGu && <path d={selectedGu.d} />}
    </clipPath>
    <clipPath id="selected-place-clip">
      {selectedPlace && <path d={selectedPlace.d} />}
    </clipPath>
  </defs>
  {/* …자치구, 장소, 경계선 다시 그리기… */}
  {selectedPlace && selectedGu && (
    <>
      {/* ① 장소 경계 중 자치구 안에 있는 부분 */}
      <g clipPath="url(#selected-gu-clip)">
        <path
          d={selectedPlace.d}
          className="stroke-selected"
          fill="none"
          strokeWidth={2}
        />
      </g>
      {/* ② 자치구 경계 중 장소 안에 있는 부분 */}
      <g clipPath="url(#selected-place-clip)">
        <path
          d={selectedGu.d}
          className="stroke-selected"
          fill="none"
          strokeWidth={2}
        />
      </g>
    </>
  )}
</svg>;
```

- 색은 도안의 `#3D3A36` → semantic 토큰 `--selected`(`stroke-selected`). 두께는 도안에서 다른 장소 테두리의 약 2.25배라, 기본 두께 1인 우리 지도에서는 2로 했다.
- 지도는 Recharts가 아닌 그냥 SVG라 **나중에 그린 게 위**다. 테두리를 장소들과 같은 자리에서 그리면 그 뒤에 그려지는 옆 장소나 자치구 경계선이 덮는다. 그래서 경계선 다시 그리기(④) 뒤에 **테두리만**(`fill="none"`) 한 번 더 그린다. 아래 장소 색은 그대로 보인다.
- 화면에 보이는 장소 모양은 원래 장소가 아니라 **"장소 ∩ 자치구"**(장소 면을 자치구로 잘랐으니까)다. 그래서 테두리도 그 모양을 따라야 한다. 교집합의 테두리는 두 조각을 합친 것이다.
  - ① 장소 경계 중 자치구 **안**에 있는 부분 → 장소 경계를 자치구 모양으로 자른다.
  - ② 자치구 경계 중 장소 **안**에 있는 부분 → 자치구 경계를 장소 모양으로 자른다. 장소가 옆 자치구로 넘어가는 쪽의 가장자리가 이 부분이다.
- 처음에는 ①만 그렸다. 북촌한옥마을처럼 자치구 안에 다 들어가는 장소는 그것만으로 충분했지만, 남산공원처럼 용산구로 넘어가는 장소는 아래쪽 가장자리에 선이 없었다(아래 "문제와 해결").
- `selectedPlace && selectedGu &&` 안에 `<g>` 두 개를 넣어서, 장소를 고르지 않은 화면에서는 빈 `<g>`도 생기지 않는다. 장소를 골랐으면 자치구도 항상 있지만(그 자치구의 장소에서 찾으니까) TypeScript는 그걸 몰라서 `selectedGu`도 조건에 넣었다. 그 안에서는 둘 다 `?.` 없이 쓴다.
- `&&` 뒤에는 요소가 하나만 올 수 있어서 `<g>` 두 개를 Fragment(`<>…</>`)로 묶었다. Fragment는 화면에 태그를 만들지 않는다.
- **받아들인 한계**: 선은 경계를 가운데에 두고 그려져서(07 참고), ②의 선은 장소 모양에 잘려 안쪽 절반만 보인다. 그래서 장소가 자치구 밖으로 넘어가는 쪽 변은 다른 변보다 조금 얇을 수 있다. 명세의 "장소 ∩ 자치구 교집합 모양을 변환 스크립트에서 미리 계산해 그린다"가 이 차이까지 없애는 방법인데, 11/9 이후 "데이터" 항목으로 미뤄 둔 작업이다.
- `strokeWidth={2}`는 viewBox 좌표 단위라 확대 배율만큼 굵어진다(중구는 약 4배라 화면에서 약 8px). 07에서 경계선은 확대와 함께 굵어지게 두기로 해서 그대로 두었다. 자치구마다 굵기가 달라 보이는 게 거슬리면 이 `<path>`에만 `vectorEffect="non-scaling-stroke"`를 주면 화면 px 기준 굵기로 고정된다.

### 서울대공원 테두리는 원래 `<path>`에 조건부 클래스로

```tsx
className={cn(
  getFillColor(guLevels, seoulGrandPark.guName),
  'stroke-map-line',
  place === SEOUL_GRAND_PARK_CODE && 'stroke-selected',
  'cursor-pointer',
)}
strokeWidth={place === SEOUL_GRAND_PARK_CODE ? 2 : undefined}
```

- `selectedPlace`는 고른 자치구의 장소(`selectedGuPlaces`)에서 찾는데, 서울대공원은 `gu`가 `null`이라 여기서 못 찾는다.
- 서울대공원은 자치구 경계로 자르지 않고 맨 위에 통째로 그리고 있어서, 따로 테두리 `<path>`를 만들지 않고 그 `<path>`에 조건부로 `stroke-selected`를 준다.
- **`stroke-selected`는 `'stroke-map-line'` 뒤에** 둔다. `cn`(tailwind-merge)은 같은 속성(선 색)이 겹치면 뒤의 것을 남긴다. 처음에 순서가 반대라 선택돼도 회색 테두리가 나왔다.
- 서울대공원 클릭은 장소 `<path>`들과 같은 `onClick={() => router.push(getMapHref({ gu: null, place: SEOUL_GRAND_PARK_CODE }))}`다.

### 확대된 자치구 바탕은 `map-zoom-wall`

용산구를 확대했을 때 장소를 누르기 어려워 보였다. 원인을 두 가지로 봤다.

1. **바탕과 장소가 같은 색이었다.** 확대된 자치구 바탕이 자치구 평균 혼잡도 색이라, 장소가 전부 여유인 용산구는 바탕도 장소도 같은 초록이었다. 장소가 얇은 테두리로만 구분돼서 누를 곳이 안 보였다.
2. **마우스를 올려도 반응이 없었다.** `cursor-pointer`만 있고 색 변화가 없었다.

바탕색은 세 번 바꿔 봤다.

| 바탕                          | 결과                                                                                                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `map-zoom-face` (도안)        | 주변 자치구 `--map-outside`(`--gray-100`)와 `--gray-150`으로 거의 같은 회색이라 구분이 안 됐다. 도안은 두꺼운 옆면(입체 블록)으로 구분하는데 그건 11/9 이후 작업이다             |
| `surface-white`               | 또렷하게 떠 보이지만 지도 톤에 비해 너무 하얘서 마음에 들지 않았다                                                                                                               |
| `congestion-none` (중랑구 색) | 주변과는 구분되지만 **"데이터 없음" 색**이다. 데이터를 못 받은 장소도 이 색이라 바탕에 녹아 사라지고, 사용자는 "이 자치구 전체가 데이터가 없나?"라고 오해할 수 있다. 쓰지 않았다 |
| **`map-zoom-wall`**           | 도안에서 확대 블록의 옆면 색(`--gray-250`)이다. 주변보다 확실히 진하고, 같은 누런 회색 계열이라 지도 톤과 맞는다. 연한 혼잡도 색도 그 위에서 잘 보인다                           |

- `map-zoom-wall`로 정했다. 도안과 다르게 바꾼 점이다. 입체 블록을 만들 때는 이 색이 옆면이 되니 바탕을 `map-zoom-face`로 돌려야 한다.
- 바탕 `<path>`에서 `stroke-map-line`도 뺐다. 경계선은 장소 위에서 다시 그리고 있어서(④) 필요 없다.

### 장소 hover 색은 단계별 표로

```ts
const LEVEL_HOVER_COLOR: Record<CongestLevel, string> = {
  여유: 'hover:fill-congestion-free-hover',
  보통: 'hover:fill-congestion-normal-hover',
  '약간 붐빔': 'hover:fill-congestion-busyish-hover',
  붐빔: 'hover:fill-congestion-busy-hover',
};

// 장소 <path>의 cn(...) 안
targetPlace && LEVEL_HOVER_COLOR[targetPlace.level],
```

- `` `hover:${LEVEL_COLOR[level]}-hover` ``처럼 이어 붙이면 안 된다. Tailwind는 코드를 실행하지 않고 파일 글자만 읽어서, 완성된 클래스 이름이 파일에 **그대로** 적혀 있어야 CSS를 만든다. 그래서 `LEVEL_COLOR`와 같은 모양의 표를 하나 더 만들었다. 09의 차트 점에서 `` `var(--color-congestion-${…})` ``로 이어 붙인 건 Tailwind 클래스가 아니라 브라우저가 실행 중에 찾는 CSS 변수라서 괜찮았다.
- `-hover` 토큰 네 개는 `tokens.md`에 있는 값이다. 데이터 없는 장소(`fill-congestion-none`)용 hover 토큰은 없어서 그 장소는 hover 없이 둔다. 그래서 `targetPlace &&`로 확인한다.
- 아주 작은 장소는 확대해도 작다. 그런 장소는 패널의 장소 목록(각 줄이 `Link`)으로 고르면 되고, 휠로 더 확대하는 기능(2-Z)이 생기면 지도에서도 고르기 쉬워진다.

## 문제와 해결

### 버튼 표시 조건이 자치구 이름을 글자로 그림

- **원인**: 처음에 `gu || place && <Button />`처럼 썼고, 저장할 때 Prettier가 `gu || (place && <Button />)`로 괄호를 넣었다. `&&`가 `||`보다 먼저 계산되기 때문이다. `||`는 왼쪽이 truthy면 **왼쪽 값을 그대로** 돌려줘서, 중구 화면에서는 버튼 대신 `'중구'`라는 글자가 패널 맨 위에 그려졌다. 서울대공원만 고쳐지고 다른 자치구 화면의 버튼이 모두 사라졌다. 타입 검사와 lint는 통과했다.
- **해결**: `(gu || place) && <Button />`. "하나라도 있으면"을 괄호로 먼저 계산한 뒤 `&&`로 잇는다. 둘 다 `null`이면 `null && …`도 `null`이라 아무것도 안 그려진다.
- **교훈**: Prettier가 넣어 준 괄호는 연산자 우선순위를 그대로 보여 준다. 의도와 다르게 묶였는지 확인하는 단서가 된다.

### 자치구 밖으로 넘어간 장소는 테두리가 일부만 그려짐

- **증상**: 배포 주소에서 남산공원(`/?gu=중구&place=POI091`)을 고르니, 초록 영역의 위쪽만 검은 테두리가 있고 아래쪽 가장자리에는 선이 없었다.
- **원인**: 남산공원의 실제 영역은 용산구까지 이어진다. 장소 면은 중구로 잘려서, 화면의 초록 영역 아래쪽 가장자리는 **장소 경계가 아니라 중구 경계**다. 그런데 테두리는 장소의 원래 경계를 중구로 자른 것뿐이라, 용산구 쪽에 있던 장소 경계는 통째로 잘려 나가고 중구 경계 쪽에는 그린 선이 원래 없었다.
- 처음 만들 때는 이 문제를 "경계에 걸친 변은 선이 절반 잘려 얇다" 정도로 잘못 짐작했다. 장소가 자치구 안에 다 들어가는 경우(북촌한옥마을)만 보면 문제가 안 보인다.
- **해결**: 장소 모양 clipPath(`selected-place-clip`)를 하나 더 등록하고, 자치구 경계를 그걸로 자른 선(②)을 같이 그렸다. 위 "고른 장소 테두리" 항목 참고.

### hover 클래스를 자치구 `<path>`에 넣음

- **원인**: hover는 장소에 줘야 하는데 확대된 자치구 바탕 `<path>`에 넣었다. `targetPlace`는 장소 `map` 콜백 **안에서만** 있는 변수라 `Cannot find name 'targetPlace'` 오류가 났다. 이어서 장소 `<path>`로 옮길 때는 hover 대신 `targetPlace && 'stroke-selected'`를 넣어서, "데이터가 있는 모든 장소에 선택 테두리"라는 뜻이 됐다(바로 뒤 `stroke-map-line`이 이겨서 효과는 없었다).
- **해결**: 장소 `<path>`의 `cn` 안에 `targetPlace && LEVEL_HOVER_COLOR[targetPlace.level]`. 선택 테두리는 ⑤에서 따로 그리고 있어서 장소 `<path>`에서는 신경 쓰지 않는다.
- `LEVEL_HOVER_COLOR`를 여유 하나만 적었을 때 `Record<CongestLevel, string>`이 나머지 세 단계가 빠졌다고 잡아 줬다.

### 테두리 `<path>`를 JSX 안에서 `return (`으로 감쌈

- **원인**: 위쪽 장소 `map` 콜백을 따라 `return ( <path /> )`로 썼다. 여기는 함수가 아니라 JSX 안이라 `return (`은 코드가 아니라 화면에 찍히는 글자가 된다. `d={}`도 비어 있어서 `JSX attributes must only be assigned a non-empty 'expression'` 오류가 났다.
- **해결**: `{selectedPlace && ( <g …><path … /></g> )}`. `key`(여러 개를 `map`으로 만들 때만 필요)와 `onClick`(이미 고른 장소)도 뺐다.

## 새로 배운 것

### `&&`와 `||`가 섞이면 `&&`가 먼저

- `a || b && c`는 `a || (b && c)`다. 곱셈이 덧셈보다 먼저인 것과 같다.
- JSX에서 `조건 && <태그 />`는 조건이 falsy면 **그 falsy 값**을 돌려준다. `null`, `undefined`, `false`, `''`는 아무것도 안 그리지만 `0`은 화면에 `0`이 찍힌다. `a || (…)`에서는 `a`가 truthy면 `a` 자체가 그려진다.
- 여러 조건을 묶을 때는 괄호로 의도를 먼저 정한다: `(gu || place) && <Button />`.

### tailwind-merge는 뒤에 적은 것이 이긴다

- `cn('stroke-map-line', 조건 && 'stroke-selected')`: 조건이 참이면 둘이 같은 속성(선 색)이라 뒤의 `stroke-selected`만 남는다.
- 그래서 **기본값을 먼저, 조건부 덮어쓰기를 나중에** 적는다. 순서를 바꾸면 조건이 참이어도 기본값이 이긴다.
- `strokeWidth` 같은 prop은 클래스가 아니라서 이 순서와 상관없다.

### 변수는 선언된 범위 안에서만 보인다

- `selectedGuPlaces.map((p) => { const targetPlace = …; return <path /> })`의 `targetPlace`는 그 콜백 안에서만 쓸 수 있다. 바깥의 다른 `<path>`에서 쓰려면 그 자리에서 다시 찾아야 한다. 테두리용 `selectedPlace`를 컴포넌트 위쪽에 따로 만든 이유다.
