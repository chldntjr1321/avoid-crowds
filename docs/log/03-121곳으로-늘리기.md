## 결정과 이유

### 장소 → 구 배정: mapshaper `-join … largest-overlap`
- 장소 목록에는 자치구 열이 없어서, 장소 영역이 **가장 많이 겹치는 구**로 정했다. `-join`은 지금 레이어(장소)의 각 도형에 다른 레이어(구)의 `properties`를 복사해 붙이는 명령이고, `largest-overlap`은 여러 구와 겹칠 때 가장 많이 겹치는 하나를 고르는 옵션이다.
- 결과는 문서와 같았다: 종로 14, 중구·용산·송파 10, 강남·마포 8, … 중랑 0, 과천시 1(서울대공원).

### 구 배정용 후보(서울 + 과천)를 지도용(서울만)과 따로 만들었다
- 서울대공원이 과천시에 있어서 후보에 과천이 없으면 엉뚱한 서울 구로 간다.
- 그렇다고 지도용 `guGeoJson`에 과천을 넣으면 세 곳이 달라진다. 직접 비교했다.
  - `districts.json`에 26번째 "구"가 생긴다.
  - `fitSize`가 과천까지 맞추느라 지도 전체가 약 43px 위로 밀린다.
  - 과천이 강북으로 분류돼 한강 선이 830px → 1208px로 늘어난다(과천 둘레가 가짜 한강이 됨). `SOUTH_OF_RIVER`에 과천을 넣으면 830px로 돌아온다.
- 과천을 지도에 "구처럼" 그릴지는 화면 작업 때 정한다. 지금은 문서대로 `districts.json`은 25개.

### 대림역은 영등포구 그대로 (수동 보정 안 함)
- 구로구·영등포구 경계에 걸쳐 있다. 역 주소는 구로구지만 면적은 영등포가 더 크고(56:44), 역 이름도 영등포구 대림동에서 왔다.
- 정답이 없는 경우라 예외 표를 만들지 않고 면적 규칙 하나로 간다. 어느 쪽에 두든 두 구 모두 장소가 4 ~ 5곳 남는다.

### `places.json` 모양: `{ code, name, guName, d }`
- `Place` 타입과 같은 이름으로 바꿔 저장했다(`AREA_CD` → `code`, `sggnm` → `guName`). 서울시 이름을 앱 이름으로 바꾸는 일을 스크립트에서 한 번만 한다.
- `bbox`는 뺐다. 구는 클릭하면 확대하지만 장소는 상세 화면으로 가서 쓸 곳이 없다.
- 구와 **같은 `toPath`**(같은 투영)로 path를 만들어야 장소가 구 위 제자리에 겹친다.

### `places.json`은 `import`로 읽는다
- `readFileSync`는 실행할 때 파일 경로를 찾아야 해서 배포 서버에서 경로가 달라질 수 있다. `import`하면 빌드 때 코드에 같이 묶인다. `tsconfig`의 `resolveJsonModule` 덕분에 타입도 자동으로 붙는다.

### 10개씩 나누지 않고 한 번에 보낸다
- 문서에는 "요청이 몰리면 거절될 수 있으니 10개씩"이라고 적어 두었지만, 확인한 사실이 아니라 걱정이었다. 먼저 한 번에 보내 보고 문제가 생기면 나누기로 했다.
- 결과: 거절 응답은 없었고 0.32 ~ 0.52초에 끝났다(1곳일 때 0.354초와 거의 같음, 동시에 보내서 가장 늦은 응답 하나만큼만 기다리기 때문). 10개씩이면 13묶음을 차례로 기다려야 한다.

> 면접용: "121곳을 몇 개씩 나눠 보낼지 처음엔 걱정만으로 10개로 정했는데, 실제로 동시에 보내 보니 거절 없이 0.3 ~ 0.5초에 끝나서 나누지 않았습니다. 대신 가끔 생기는 연결 끊김은 `Promise.allSettled`로 그 장소만 빼고 나머지를 내려주게 했습니다."

### `Promise.all` → `Promise.allSettled`
- `Promise.all`은 121곳 중 1곳만 실패해도 전체가 실패해 `/api/places`가 500이 된다.
- `allSettled`는 모두 끝날 때까지 기다리고 `{ status: 'fulfilled', value }` 또는 `{ status: 'rejected', reason }` 보고서를 준다. 성공만 골라 반환한다.
- **전부 실패하면 `throw`.** `allSettled`는 절대 던지지 않아서, 그대로 두면 빈 배열이 성공으로 나가 캐시에 저장되고 빌드도 빈 지도로 통과한다.

### 연결 실패에도 장소코드를 붙였다 (`try...catch` + `cause`)
- `fetch`는 응답을 아예 못 받으면 `TypeError: fetch failed`를 던진다. 이건 `fetchPlace`의 가드 절보다 먼저 나서 장소코드가 없다.
- `fetch(url)` 한 줄만 `try`로 감쌌다. 다른 줄까지 넣으면 장소코드를 넣어 던진 다른 오류까지 `catch`가 잡아서 덮어 버린다. `res`는 `try` 밖에서 써야 해서 `let res: Response`를 먼저 만들었다.
- 다시 던질 때 `new Error(메시지, { cause: error })`로 원래 오류를 붙였다. 이 덕분에 실제 원인(`ECONNRESET`)을 볼 수 있었다.

## 문제와 해결

### `-i placeFile.json`에 `.shp`를 `readFileSync`로 넣었더니 `JSON parsing error`
- **원인**: mapshaper는 이름표의 확장자(`.json`)를 보고 형식을 짐작한다. 내용은 shapefile 바이트라 JSON으로 읽다 실패했다. `readFileSync`로는 `.shp` 한 파일만 읽혀서 속성(`.dbf`)도 빠진다.
- **해결**: `-i` 뒤에 디스크의 실제 경로를 그대로 적었다. mapshaper가 `.dbf`, `.prj`도 같이 읽는다.

### `-dissolve sggnm`으로 장소에 구를 붙이려다 `Missing a field named: sggnm`
- **원인**: `-dissolve`는 같은 값끼리 도형을 합치는 명령이다. 장소에는 아직 `sggnm`이 없고, 붙이는 것은 `-join`이다.
- **해결**: `-join extended-gu.json largest-overlap`.

### `output['guPlus과천.json']`에서 `undefined.toString()`
- **원인**: `applyCommands`의 결과는 `-o` 뒤에 쓴 이름을 키로 갖는 객체다. `-o gu.json`으로 내보내고 다른 키로 꺼냈다.
- **해결**: `-o` 이름과 꺼내는 키를 같게 맞췄다.

### `places`의 `name`에 구 이름이 들어감
- **원인**: `districts` 코드를 복사하면서 `name: f.properties.sggnm`이 남았다. 장소에서 `sggnm`은 소속 구다.
- **해결**: `AREA_NM`으로 바꿨다. 오류 메시지도 장소 이름이 나오게 고쳤다.

### `failedResults.reason`: `Property 'reason' does not exist on type 'any[]'`
- **원인**: `.map((r) => r.reason)`을 이미 해서 배열 안에 오류들만 남아 있다. 배열에는 `reason` 칸이 없다.
- **해결**: `for...of`로 하나씩 `console.error`.

### 실패 로그에 `cause`가 안 보임
- **원인**: `` `실패 ${reason}` ``처럼 오류를 템플릿 문자열에 넣으면 `Error: 메시지` 한 줄로 바뀌고 `cause`는 버려진다.
- **해결**: `console.error(reason)`으로 객체를 그대로 넘겼다.

### 121곳 중 가끔 1곳이 빠짐 (`ECONNRESET`)
- **관찰**: 19번 중 1번, `POI118 서울시 API 연결 실패` → `[cause]: TypeError: fetch failed` → `[cause]: read ECONNRESET`. 응답을 읽는 중에 서버가 연결을 끊었다.
- **원인 후보**: ① 동시 요청이 많아서 서버가 끊었다. ② Node `fetch`가 재사용한 연결을 서버가 이미 닫았다(두 번 다 한동안 쉰 뒤 첫 요청으로 보임). 아직 단정할 수 없다.
- **지금 대응: 고치지 않고 지켜본다.** 원인에 따라 해결책이 다르고(①이면 나눠 보내기, ②면 연결 실패 시 한 번 다시 부르기), 잘못 고르면 느려지기만 하고 효과가 없다.
- **놔둬도 되는 근거는 원인이 아니라 빈도다.** 원인이 ①이어도 다음 갱신 때 똑같이 121개를 보내니 원인은 그대로다. 그래도 괜찮은 이유는 실패가 드물고(19번 중 1번) 한 곳씩이라서, `allSettled`로 그 장소만 빠지고 **다음 갱신(5분 뒤)에 저절로 회복**되기 때문이다.
- **영향 계산**: 하루 갱신 최대 288번 × 약 1/19 ≈ 하루 15번 정도, 한 장소가 5분씩 빠진다. 표본이 19번이라 대략적인 값이다.
- **다시 손볼 조건**: 측정 기간에 로그를 모아 빈도가 늘거나 여러 곳이 한꺼번에 빠지면 원인에 맞게 고친다. 로그에 시각과 직전 요청 이후 지난 시간을 남기면 ①과 ②를 가를 수 있다.
- "마지막 성공 데이터"를 구현하면 빠진 5분 동안에도 5분 전 값이 보여서, 사용자는 실패를 느끼지 못한다.

> 면접용: "121곳 중 한 곳이 가끔(19번 중 1번) 연결이 끊겼습니다. 원인 후보가 두 개고 해결책이 서로 달라서, 확실하지 않은 상태로 고치지 않았습니다. 대신 `allSettled`로 그 장소만 빠지게 했고, 캐시가 5분마다 갱신되니 다음 갱신 때 다시 불러와 저절로 회복됩니다. 하루로 치면 한 장소가 5분씩 15번 정도 빠지는 수준이라 지금은 감수하고, 로그를 모아서 빈도가 늘면 원인에 맞게 고치기로 했습니다."

## 확인한 사실

- mapshaper `applyCommands`는 디스크에 파일을 쓰지 않는다. `-i` 이름은 두 번째 인자 객체에서 먼저 찾고, 없으면 디스크에서 찾는다. 결과는 `-o` 이름을 키로 한 객체이고 값은 `Buffer`다.
- 배열을 그대로 `-i`에 넣으면 GeoJSON이 아니라 표로 읽힌다. `{ type: 'FeatureCollection', features }`로 감싸야 한다.
- `-dissolve`는 이름 글자만 비교한다. 전국에는 `중구`(서울·부산·대구·대전·울산), `강서구`(서울·부산)처럼 이름이 겹치는 곳이 있어서, 먼저 시도로 거른 뒤 합쳐야 한다.
- 서울대공원 path는 y 약 885로, 서울 기준 1000×1000 투영 안에 들어온다.
- 서울시 API에 121곳을 동시에 보내도 거절 응답은 없었다.
- `allSettled`로 바꾼 뒤에는 `/api/places`가 200이어도 121곳 전부라는 뜻이 아니다. 장소 수나 `실패` 로그를 봐야 한다.

## 새로 배운 것

- **`-dissolve` vs `-join`**: `-dissolve 칸이름`은 같은 값끼리 도형을 합친다(다른 칸은 사라짐). `-join 레이어이름표`는 도형은 그대로 두고 다른 레이어의 속성을 붙인다.
- **`find` vs `filter`**: 조건에 맞는 첫 칸 하나 / 맞는 칸 전부를 담은 배열.
- **옵셔널 체이닝 `?.`**: 앞이 `undefined`이면 오류 대신 `undefined`를 돌려준다.
- **이름 없는 `import`**: `import '파일'`은 실행만 하고 값을 받지 않는다. 값을 쓰려면 `import 이름 from '파일'`.
- **`Promise.all` / `Promise.allSettled`**: 하나 실패하면 전체 실패 / 모두 끝날 때까지 기다리고 결과 보고서를 준다. `filter((r) => r.status === 'fulfilled')`로 좁히면 `value`를 쓸 수 있다.
- **`for...of`**: 배열 칸을 하나씩 꺼내 실행만 한다. 새 배열이 필요하면 `map`.
- **`try...catch`**: `try` 안에서 던진 오류를 `catch`가 받는다. `try` 안에서 만든 `const`는 밖에서 못 쓴다.
- **`Error`의 `cause`**: `new Error(메시지, { cause: 원래오류 })`. 장소코드처럼 우리 정보를 더하면서 원래 원인도 잃지 않는다. `console.error`에 객체를 그대로 넘겨야 보인다.
- **`ECONNRESET`**: 연결은 됐는데 읽는 중에 상대가 끊었다. `ENOTFOUND`(주소 없음), `ETIMEDOUT`(시간 초과)과 구분된다.
- **이름은 "어디에 쓰나"로도 지을 수 있다**: `seoulAndGwacheonGuGeoJson` → `extendedGuGeoJson`. 짧아진 만큼 주석으로 이유를 남긴다.
