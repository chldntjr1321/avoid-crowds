## 결정과 이유

### 패널 내용 분기는 "데이터 없음 → 장소 → 자치구 → 서울 전체"로 평평하게

```tsx
let content: React.ReactNode;

if (!data) {
  content =
    errorUpdateCount > 0 ? (
      <ErrorState onRetry={() => refetch()} isRetrying={isFetching} />
    ) : (
      <p className="text-[13px] text-text-secondary" role="status">
        불러오는 중
      </p>
    );
} else if (place) {
  // getValidMapQuery를 통과한 place는 항상 gu가 있음
  content = selectedPlace ? (
    <PlaceDetail place={selectedPlace} />
  ) : (
    <p className="text-[13px] text-text-secondary" role="alert">
      정보를 불러오지 못했어요
    </p>
  );
} else if (gu) {
  const selectedGuPlaces = data.filter((d) => d.guName === gu);
  const sortedGuPlaces = sortByMostCrowded(selectedGuPlaces);
  content = <PlaceList places={sortedGuPlaces} />;
} else {
  content = null; // 서울 전체 (나중에 TOP 5)
}
```

여기까지 세 번 모양이 바뀌었다.

1. **`if (place)`와 `if (gu)`를 따로 둠** → `?gu=중구&place=POI091`에서는 둘 다 참이라 두 `if`가 모두 실행되고, 아래 `if (gu)`가 `PlaceDetail`을 `PlaceList`로 덮어썼다. 화면에는 목록이 보였다.
2. **`if (data) { if (gu) { if (place) … } }` 3단 중첩** → 동작은 맞았지만 목록을 먼저 넣고 장소면 덮어쓰는 방식이라, 장소 화면에서도 `filter`와 정렬을 매번 하고 버렸다. `content`가 마지막에 무엇인지 알려면 끝까지 읽어야 했다.
3. **지금 모양** → 두 가지 생각으로 중첩을 풀었다.
   - **데이터가 없는 경우를 먼저 처리한다.** 그 아래에서는 `data`가 있다는 게 확실해서 `if (data)` 한 단계가 빠진다. `getValidMapQuery`에서 "틀린 경우부터 먼저 return"한 것과 같은 생각이다.
   - **`place`가 있으면 `gu`도 반드시 있다.** `FloatingPanel`이 받는 `gu`, `place`는 `useMapQuery` 훅 안에서 `getValidMapQuery`를 이미 통과한 값이다. 이 함수는 `gu`가 틀리면 `place`도 `null`로 만들고, `place`가 그 자치구 소속이 아니면 `place`만 `null`로 만든다. 그래서 패널에서 `gu`를 먼저 확인하지 않고 `place`를 먼저 봐도 된다.

`else if`로 이으면 "넷 중 하나만" 실행되고, 위에서 아래로 한 번만 읽으면 된다. 두 번째 생각은 `getValidMapQuery`의 규칙에 **기대는** 것이라서, 왜 `gu`를 확인하지 않는지 `else if (place)` 블록 안에 주석으로 남겼다. 마지막 `else`도 지우지 않았다. 없어도 `content`가 `undefined`라 화면은 같지만, "서울 전체일 때는 비워 둔다"는 뜻이 코드에서 사라진다.

### 장소를 못 찾을 때와 불러오는 중은 태그로 감싸고 `role`을 붙인다

- 주소에 `place`가 있어도 `data`에서 그 장소를 못 찾을 수 있다. 서울시에서 그 장소만 실패해 빠진 경우다. 이때는 "정보를 불러오지 못했어요"를 보여 준다.
- 글자만 `content`에 넣어도 React는 그대로 그린다. 그래도 `<p>`로 감싼 이유는 두 가지다. 클래스를 붙일 곳이 생겨서 `ErrorState`의 설명 글과 같은 `text-[13px] text-text-secondary`를 줄 수 있고, `role`을 붙일 수 있다.
- **`role="status"`**: "불러오는 중"은 문제가 아니라 진행 상황이다. 스크린리더가 지금 읽던 걸 끝내고 차례가 되면 읽어 준다.
- **`role="alert"`**: "정보를 불러오지 못했어요"는 실패 안내라서 `ErrorState`와 같은 `alert`다. 스크린리더가 읽던 걸 끊고 바로 읽어 준다.

### 돌아가기 버튼과 제목은 `return` 위에서 변수로 정한다

```tsx
const selectedPlace = data?.find((d) => d.code === place);
// ...content 분기...

const backHref = place
  ? getMapHref({ gu, place: null })
  : getMapHref({ gu: null, place: null });
const backLabel = place ? `${gu} 장소 목록` : '서울 전체';
const panelTitle = place ? '' : (gu ?? '서울 전체');
```

- 버튼 모양 코드(`<Button asChild><Link>…`)는 하나로 두고, 화면마다 다른 **주소, 글자, 제목** 세 값만 위에서 정한다. `content`를 위에서 정하고 JSX에서는 `{content}`만 쓰는 것과 같은 방식이다.
- 세 값 모두 **`place`를 기준으로** 가른다. `selectedPlace`(찾은 장소)를 기준으로 하면 데이터를 받는 중이거나 그 장소만 실패했을 때 `undefined`라서, 장소 화면인데 버튼이 "서울 전체"로 나온다. 아래 `content` 분기도 `place`로 화면을 나누고 있어서, 같은 기준을 써야 패널 내용과 버튼이 어긋나지 않는다.
- 버튼 글자의 자치구 이름도 `selectedPlace?.guName`이 아니라 이미 가진 `gu`를 쓴다. 같은 이유로 `selectedPlace`가 없으면 "undefined 장소 목록"이 나온다.
- `selectedPlace`는 원래 `else if (place)` 블록 안에서 만들었는데, 제목에도 쓸까 해서 블록 밖 위쪽으로 옮겼다. 그 자리에서는 `data`가 없을 수 있어서 `data?.find`다. 결국 제목에는 쓰지 않게 됐지만, 지도 쪽과 같은 이름으로 위에 한 번 찾아 두는 모양이 됐다.
- 이 버튼은 07에서 `href="/"`를 직접 적었는데, 이제 주소가 두 가지라 둘 다 `getMapHref`로 만든다. "주소는 `getMapHref` 한곳에서 만든다"는 06의 결정과도 맞게 됐다.

### 장소 화면에서는 패널 제목을 그리지 않고, 장소 이름이 `<h2>`가 된다

- 도안 `03-place`에서 버튼 아래 큰 제목은 "남산공원 [보통]"이다. 그런데 장소 이름과 단계는 `PlaceDetail`이 이미 그린다. 그래서 장소 화면에서는 패널 쪽 `<h2>`를 그리지 않고, `PlaceDetail`의 장소 이름을 `<p>`에서 `<h2>`로 바꿨다. 화면마다 제목 태그는 하나씩이다.
- `panelTitle`이 장소 화면에서 `''`이어도 `<h2>{panelTitle}</h2>`라고 쓰면 빈 `<h2>` 태그가 남는다. 패널 `<aside>`의 `gap-4` 때문에 높이 0인 태그에도 위아래 간격이 붙어 버튼과 장소 정보 사이가 16px 더 벌어지고, 스크린리더가 내용 없는 제목을 읽는다. 그래서 `{panelTitle && <h2>…</h2>}`로 **태그 자체를 그리지 않는다.** `'' && …`의 결과는 `''`이고, React는 빈 문자열을 아무것도 그리지 않는다.
- 서울 전체와 자치구 화면 제목은 원래 `<h2>` 안에 있던 `gu ?? '서울 전체'`를 그대로 가져왔다.

### 제목 크기는 화면마다 도안 값대로

- 도안 HTML 값: 서울 전체 18px(굵기는 `<h2>` 기본 bold), 자치구와 장소 20px · 800.
- 패널 `<h2>` 하나가 서울 전체와 자치구 제목을 같이 그려서, `className={gu ? 'text-xl font-extrabold' : 'text-lg font-bold'}`로 골랐다. 둘 중 하나를 고르는 거라 `cn` 없이 삼항 연산자로 충분하다.
- `className={gu && '…'}`로는 안 된다. 서울 전체에서 `className={null}`이 되어 타입 오류가 나고(`className`은 `string | undefined`만 받는다), 서울 전체용 클래스도 사라진다.
- `cn('text-lg font-bold', gu && 'text-xl font-extrabold')`처럼 기본값 + 덧붙이기로 쓸 때는 `cn`이 필요하다. `text-lg`와 `text-xl`이 같이 붙으면 `cn`(tailwind-merge)이 **뒤의 것만** 남긴다. `cn` 없이 문자열로 붙이면 어느 쪽이 이길지는 적은 순서가 아니라 CSS 파일 안에서 클래스가 정의된 순서로 정해진다.

### 혼잡도 배지는 새 컴포넌트가 아니라 shadcn `Badge`의 variant로

- 배지는 장소 상세에도, 도안 `02-district`의 장소 목록 줄마다에도 붙는다. 그래서 부품으로 뺀다.
- 만드는 방식은 `06-conventions.md`에 이미 정해 두었다. "모양만 다른 부품은 새 파일을 만들지 않고 shadcn 파일 안에 variant를 추가한다." `<Button variant="outline">`과 같은 방식이다.
- `pnpm dlx shadcn add badge`로 `src/components/ui/badge.tsx`를 받았다. 새 npm 패키지는 설치되지 않았다(`class-variance-authority`는 `Button` 때문에 이미 있다).
- `variants.variant` 안에 혼잡도 variant 다섯 개를 추가했다. shadcn 원래 variant(`default`, `outline` 등)는 지우지 않았다. 안 써도 동작에 영향이 없고, 원본 구조가 남아 있어야 나중에 우리가 무엇을 추가했는지 바로 보인다.

```ts
free: 'bg-congestion-free text-foreground',
normal: 'bg-congestion-normal text-foreground',
busyish: 'bg-congestion-busyish text-foreground',
busy: 'bg-congestion-busy text-foreground',
none: 'bg-congestion-none text-foreground',
```

- variant마다 **완성된 클래스 이름**을 적는다. `` `bg-congestion-${…}` ``처럼 이어 붙이면 Tailwind가 그 클래스를 만들지 않아 색이 안 나온다. Tailwind는 코드에 글자 그대로 적힌 클래스만 만든다.
- 모든 variant가 같이 쓰는 기본 클래스의 `rounded-4xl`(알약 모양)을 `rounded-sm`(2px)으로 바꿨다. `tokens.md`에 "버튼·뱃지 2px"로 정해져 있다.
- shadcn 원본에 없는 variant가 왜 있는지 알 수 있게 `badgeVariants` 바로 위에 주석을 달았다. 파일 맨 위보다 variant를 고칠 사람이 바로 보는 자리라서 그쪽에 뒀다.
- 제목 옆 배지는 도안에서 13px(MD)라 쓰는 쪽에서 `className="text-[13px]"`를 넘겼다. `Badge`가 `cn(badgeVariants(...), className)`으로 합쳐서 뒤에 오는 `text-[13px]`가 기본 `text-xs`를 이긴다.

### 한국어 단계 → variant 이름 변환은 `getBadgeVariant`

```ts
type BadgeVariant = 'free' | 'normal' | 'busyish' | 'busy';
const LEVEL_BADGE_VARIANT: Record<CongestLevel, BadgeVariant> = {
  여유: 'free',
  보통: 'normal',
  '약간 붐빔': 'busyish',
  붐빔: 'busy',
};

// 혼잡도 단계 -> Badge variant 이름 변환 함수
export function getBadgeVariant(level: CongestLevel): BadgeVariant {
  return LEVEL_BADGE_VARIANT[level];
}
```

- `place.level`은 `'여유'` 같은 한국어인데 variant 이름은 `'free'` 같은 영어라 둘을 잇는 표가 필요하다. `seoul-map.tsx`의 `LEVEL_COLOR`와 같은 `Record<CongestLevel, …>` 모양이다. 단계 하나라도 빠지면 타입 오류가 난다.
- **값 타입을 `string`으로 적으면 `Badge`가 받지 않는다.** `Badge`의 `variant`는 `'free' | 'busy' | …`처럼 정해진 이름만 받는데, `Record<CongestLevel, string>`이라고 적으면 TypeScript는 값이 `'free'`였다는 걸 잊고 `string`으로만 기억한다. 그래서 `Type 'string' is not assignable to type '"link" | "default" | ... | "free" | ...'` 오류가 났다. 이름을 `|`로 나열한 `BadgeVariant` 타입으로 좁혀서 해결했다.
- 표는 함수 **밖**에 한 번만 둔다. 함수 안에 두면 부를 때마다 같은 객체를 새로 만든다.
- "단계 → 다른 값" 변환이라 `06` 문서 규칙대로 `lib/congestion.ts`에 뒀다. 장소 목록과 09의 예측 그래프 점 색에서도 같은 함수를 쓴다.

### 인구는 `formatPopulation`, 1만 명 미만은 명 단위

```ts
export function formatPopulation({ min, max }: PopulationRange): string {
  if (min < 10000) {
    const formattedMin = min.toLocaleString('ko-KR');
    const formattedMax = max.toLocaleString('ko-KR');

    return `약 ${formattedMin}~${formattedMax}명`;
  }
  const formattedMin = (min / 10000).toFixed(1);
  const formattedMax = (max / 10000).toFixed(1);

  return `약 ${formattedMin}~${formattedMax}만명`;
}
```

| 입력        | 결과             |
| ----------- | ---------------- |
| 300~500     | 약 300~500명     |
| 8000~8500   | 약 8,000~8,500명 |
| 10000~12000 | 약 1.0~1.2만명   |
| 32000~34000 | 약 3.2~3.4만명   |

- 도안은 "약 0.9~1.1만명"처럼 만 단위다. 장소 목록, 서울 전체의 붐비는 곳 목록에도 같은 표기가 나와서 함수로 뺐다.
- 기준이 두 번 바뀌었다.
  1. **기준 없음**: 300~500이 "약 0.0~0.1만명"이 됐다. 사람 적은 곳을 찾는 서비스라 오히려 이런 장소가 중요하다.
  2. **`min < 1000`**: 도안 예시 "0.9~1.1만명"을 그대로 살리려고 1000으로 잡았다. `max`가 아니라 **`min`** 을 기준으로 한 이유는, `max` 기준이면 800~1200이 "0.1~0.1만명"처럼 두 숫자가 같아져 범위가 사라지기 때문이다.
  3. **`min < 10000`**: 실제 화면에서 용산역이 "약 0.8~0.8만명"으로 나왔다. 아래 "문제와 해결"에 정리했다.
- 명 단위일 때는 `toLocaleString('ko-KR')`로 쉼표를 넣는다. `'ko-KR'`을 적어 두면 서버와 브라우저의 언어 설정이 달라도 결과가 같다.
- 부르는 쪽은 `formatPopulation(place.population)`이다. `place.population`이 이미 `{ min, max }` 모양(`PopulationRange`)이라 새 객체를 만들어 넘길 필요가 없다.

| 기준 시각 표기    | `14:05` (시각만)                       | `measuredAt` 그대로 (날짜 포함) | 날짜까지 보여 주기로 했다. 그래서 시각만 꺼내려고 만든 `formatTime`은 쓰는 곳이 없어져 지웠다                              |
| 정보 목록         | 지금 인구, 기준 시각 두 줄             | 현재 인구 한 줄                 | 기준 시각이 제목 위로 올라갔다. 라벨도 "지금 인구" → "현재 인구"                                                           |
| 현재 인구 값      | 13px 굵게                              | 16px(`text-base`) 굵게          | "지금 몇 명인가"가 이 서비스에서 가장 중요한 정보라 값만 키웠다. 라벨까지 키우면 라벨과 값의 차이가 줄어 값이 덜 눈에 띈다 |
| 안내 문구 박스    | 문구가 먼저, "서울시 안내 문구"는 아래 | "서울시 안내 문구"를 위에       | 제목 역할을 하는 라벨이라 위가 자연스럽다                                                                                  |
| 안내 문구 줄 간격 | `line-height: 1.6`                     | 넣지 않음 (기본 1.5)            | 13px 기준 한 줄에 1.3px 차이라 뺐다                                                                                        |

기준 시각 줄의 색은 디자인 시스템 Eyebrow의 MUTED 색인 `text-muted-foreground`를 썼다. 주황(ACCENT)은 "NOW · TOP 5 CROWDED"처럼 눈길을 끌어야 하는 라벨용이라, 장소 이름보다 덜 중요한 보조 정보에는 맞지 않는다. 바로 아래 "현재 인구" 라벨 색과도 같아서 "보조 정보는 이 회색"으로 화면 안 규칙이 하나가 된다.

### 간격은 도안 구조 그대로: 덩어리는 형제로, 사이는 16px

```
<div className="flex flex-col gap-4">              ← 덩어리 사이 16px
  <div className="flex flex-col gap-1">            ← 기준 시각 + 제목 줄, 4px로 붙음
    <time>2026-11-08 21:50 기준</time>
    <div className="flex items-center gap-2">      ← 이름과 배지 8px
      <h2>용산역</h2> <Badge>붐빔</Badge>
    </div>
  </div>
  <dl className="flex flex-col gap-1.5 text-[13px]"> ← 현재 인구 (라벨과 값 14px)
  <div>서울시 안내 문구 박스</div>
</div>
```

- 도안 HTML은 패널이 `gap: 16px`인 세로 flex이고, 제목 줄 · 정보 목록 · 안내 문구 박스가 모두 **형제**다. 처음에는 안내 문구 박스가 정보 목록 `<div>` **안**에 있어서 바깥 `gap-4`가 적용되지 않았다. `gap`은 바로 아래 자식들 사이에만 생긴다. 박스를 밖으로 꺼내 형제로 만들었다.
- 글자 크기 `text-[13px]`는 묶음(`<dl>`, 박스 `<div>`)에 한 번만 주고 안쪽이 물려받게 했다.

### 시맨틱 태그: `<dl>`, `<time>`, `<p>`

- **`<dl>` / `<dt>` / `<dd>`**: "현재 인구 → 약 8,000~8,500명"은 같은 종류 항목의 나열(`<ul>`)이 아니라 **이름표와 값의 짝**이다. HTML에는 이 짝을 위한 태그가 따로 있다. 도안 HTML도 이 부분을 `<dl>`로 만들었다. `<dl>` 안에서 `<dt>`와 `<dd>` 한 쌍을 `<div>`로 감싸는 것도 허용돼서, `flex`를 줄 `<div>`를 그대로 둘 수 있다.
- **`<time dateTime={place.measuredAt}>`**: 날짜·시각을 나타내는 태그다. 안의 글자가 "2026-11-08 21:50 기준"이라 "기준" 때문에 올바른 시각 형식이 아니다. `dateTime` 속성에 `measuredAt`만 따로 넣어서, 화면 글자는 그대로 두고 기계가 읽을 값을 알려 줬다. HTML은 날짜와 시각 사이를 공백으로 쓴 `"2026-11-08 21:50"` 형식도 허용한다.
- **안내 문구는 `<p>`**: 문장 단위 본문이라 `<span>`보다 `<p>`가 맞다. "서울시 문구를 인용한 것"이라는 점을 살리면 `<figure>` + `<blockquote>` + `<figcaption>`도 가능하지만 MVP는 `<p>`로 충분하다.
- 바깥 묶음과 제목 줄은 배치용이라 `<div>`가 맞다.
- `tabular-nums`를 기준 시각에 줬다. 숫자 폭을 모두 같게 맞춰서 시각이 바뀌어도 글자 길이가 들썩이지 않는다.

## 문제와 해결

### `PlaceDetail`을 붙이자 목록이 그대로 보임

- **원인**: `if (place) { content = <PlaceDetail /> }` 다음에 `if (gu) { content = <PlaceList /> }`가 따로 있었다. 장소 주소에는 `gu`도 있어서 두 번째 `if`가 덮어썼다.
- **해결**: `else if`로 이어 "넷 중 하나만" 실행되게 했다(위 "패널 내용 분기" 참고).

### 자치구 화면의 돌아가기 버튼이 지금 페이지로 감

- **원인**: 처음에는 `backHref`를 장소 화면 기준(`getMapHref({ gu, place: null })`)으로만 만들고, JSX에서 `href={backHref || '/'}`로 서울 전체를 대신하려 했다. 그런데 `getMapHref`는 `gu`가 없어도 `'/'`를 돌려주는 등 **항상 글자가 있는 문자열**을 돌려준다. `backHref`가 언제나 truthy라 `|| '/'`의 오른쪽까지 가는 일이 없었다. 자치구 화면(`?gu=중구`)에서 누르면 `/?gu=중구`, 즉 지금 페이지로 갔다.
- **해결**: `||`로 뒤에서 막지 않고, `backHref`를 만드는 줄에서 `place ? … : …`로 처음부터 값이 갈라지게 했다. 이어서 두 값이 서로 바뀌어 있던 것과, 기준이 `selectedPlace`였던 것을 `place`로 고쳤다.
- 같은 시기에 `panelTitle`도 장소 화면만 생각해서 만들어 서울 전체에서 "null 장소 목록"이 나왔다. 템플릿 리터럴은 `null`을 `"null"`이라는 글자로 바꾼다. 세 변수 모두 **세 화면을 하나씩 대입해 보는** 방식으로 확인했다.

### 장소 정보가 패널 바닥으로 밀림

- **원인**: `PlaceDetail`의 바깥 `<div>`는 패널의 `<div className="flex flex-1">` 안에 들어간다. 이 부모가 기본값 `align-items: stretch`라서 바깥 `<div>`의 높이가 패널 높이만큼 늘어난다. 그런데 바깥 `<div>`가 세로(`flex-col`)인 상태에서 이름 줄에 `flex-1`이 붙어 있었다. 세로 flex 안의 `flex-1`은 남는 **세로** 공간을 차지하라는 뜻이라, 이름 줄이 남는 높이를 다 가져가 아래 정보가 맨 아래로 밀렸다.
- **해결**: 이름 줄의 `flex-1`을 뺐다. 처음 `PlaceDetail`이 가로 배치(`flex-row justify-between`)였을 때 쓰던 클래스가 세로로 바꾼 뒤에도 남아 있었다.
- 같은 때 인구 범위도 `` `약 ${max}~${min}명` ``으로 앞뒤가 바뀌어 "약 56000~54000명"으로 나와서 고쳤다.

### 용산역 인구가 "약 0.8~0.8만명"으로 나옴

- **원인**: 개발 서버의 `/api/places`로 실제 값을 확인하니 용산역은 `{ min: 8000, max: 8500 }`이었다. 8500 / 10000 = 0.85인데 `toFixed(1)`이 반올림해 `0.8`이 되면서 두 값이 같아졌다.
- 서울시 데이터를 더 보니 인구 범위의 폭이 정해져 있었다. **1만 명 미만은 폭 500명**(5500~6000, 9000~9500), **1만 명 이상은 폭 2000명**(10000~12000, 32000~34000)이다. 폭 2000명은 소수점 한 자리(0.2만)로 구분되지만 폭 500명(0.05만)은 구분되지 않는다. 그때 121곳 중 90곳이 1만 명 미만이었다.
- **해결**: 기준을 `min < 1000`에서 `min < 10000`으로 바꿨다. 1000으로 정한 건 도안의 임시 숫자 "0.9~1.1만명"에 맞춘 판단이었는데, 실제 데이터로 보면 9000~9500 같은 범위는 만 단위로 쓸 수 없다. 쉼표 처리는 이미 만들어 둔 `toLocaleString` 그대로다.
- **교훈**: 표기 규칙은 도안의 예시 숫자가 아니라 **실제 데이터의 범위와 간격**을 보고 정한다.

## 확인한 사실

- 세 화면(`/`, `?gu=중구`, `?gu=중구&place=POI091`)에서 버튼 글자 · 버튼 주소 · 제목이 맨 위 표대로 나오고, 버튼을 누르면 실제로 이동한다.
- 서울시 인구 범위의 폭은 1만 명 미만이면 500명, 1만 명 이상이면 2000명이다.
- 서울시 응답의 기준 시각(`PPLTN_TIME`)과 예측 시각(`FCST_TIME`)은 둘 다 `"2026-11-08 17:30"`처럼 날짜와 시각 사이에 공백 하나가 있는 같은 형식이다.
- `text-[13px]`처럼 대괄호로 글자 크기만 정하면 줄 간격은 바뀌지 않고 Tailwind 기본값(`html`의 `line-height: 1.5`)이 남는다. `text-xs` 같은 기본 크기 클래스는 줄 간격도 같이 정한다.
- `pnpm dlx shadcn add badge`는 `badge.tsx` 파일 하나만 만들고 새 패키지를 설치하지 않았다. 파일 안의 `import { cn } from 'cn'`은 오타가 아니라 shadcn이 만든 npm 패키지 `cn`이다(`button.tsx`도 같다).

## 새로 배운 것

### `else if`로 이어야 "하나만" 실행된다

- 따로 쓴 `if` 두 개는 **둘 다** 검사하고, 둘 다 참이면 둘 다 실행된다. 같은 변수에 값을 넣으면 뒤의 것이 이긴다.
- `if … else if … else`는 위에서부터 처음 참인 블록 **하나만** 실행하고 나머지는 건너뛴다. 그래서 더 구체적인 조건(장소)을 덜 구체적인 조건(자치구)보다 **위에** 둔다. `?gu=중구&place=…`는 두 조건 모두 참이라, 순서가 반대면 장소 화면으로 갈 수 없다.
- 중첩을 줄이는 방법: 예외(데이터 없음)를 먼저 처리하기, 다른 곳에서 보장된 규칙(검사를 통과한 `place`에는 `gu`가 있다)을 써서 겹친 조건 풀기.

### `||`는 "값이 없을 때"만 오른쪽으로 간다

- `A || B`는 A가 falsy(`''`, `null`, `undefined`, `0`, `false`)일 때만 B다. 언제나 글자가 있는 문자열을 돌려주는 함수의 결과에 `|| '기본값'`을 붙이면 기본값은 절대 쓰이지 않는다.
- "상황에 따라 다른 값"이 필요하면 값을 만드는 줄에서 조건(`place ? … : …`)으로 가른다.

### `role="status"`와 `role="alert"`

| `role`   | 언제                        | 스크린리더                      |
| -------- | --------------------------- | ------------------------------- |
| `status` | 진행 상황 (불러오는 중)     | 읽던 걸 끝내고 차례가 되면 읽음 |
| `alert`  | 문제가 생겼다는 안내 (실패) | 읽던 걸 끊고 바로 읽음          |

- 글자가 화면에 새로 나타나도 스크린리더는 그 사실을 모른다. `role`이 있어야 "바뀐 내용이 있다"고 알려 준다.

### shadcn 컴포넌트의 variant (`cva`)

- shadcn 컴포넌트는 `class-variance-authority`의 `cva(기본 클래스, { variants: { variant: { 이름: 클래스 } } })`로 모양 버전을 정의한다. `<Badge variant="busy">`라고 쓰면 기본 클래스 + `busy`의 클래스가 붙는다.
- 새 모양이 필요하면 새 파일 대신 이 표에 한 줄을 추가한다. `variant` prop의 타입도 표의 이름들로 자동으로 정해져서, 없는 이름을 넘기면 타입 오류가 난다.
- 쓰는 쪽에서 넘긴 `className`은 `cn(badgeVariants({ variant }), className)`으로 **뒤에** 합쳐져서, 부딪히는 클래스(`text-xs` vs `text-[13px]`)는 쓰는 쪽이 이긴다.

### `Record`의 값 타입은 좁게 적는다

- `Record<CongestLevel, string>`은 "키는 단계 네 개, 값은 아무 글자"다. 표에 `'free'`를 적어도 꺼낸 값의 타입은 `string`이다.
- 값이 정해진 이름 중 하나여야 하는 곳(`variant`)에 넘기려면 값 타입을 `'free' | 'normal' | 'busyish' | 'busy'`처럼 좁혀야 한다. 그러면 표에 오타(`'fre'`)를 적어도 바로 오류가 난다.

### 숫자를 글자로: `toFixed`와 `toLocaleString`

- `(8500 / 10000).toFixed(1)` → `'0.8'`. 소수점 n자리 **문자열**을 돌려주고, 그 아래 자리는 반올림한다. 그래서 0.80과 0.85가 같은 `'0.8'`이 될 수 있다.
- `(8500).toLocaleString('ko-KR')` → `'8,500'`. 나라별 숫자 표기 규칙(천 단위 쉼표)에 맞춘 문자열이다. 지역을 적지 않으면 실행하는 환경의 언어 설정을 따라서 서버와 브라우저 결과가 달라질 수 있다.

### `<dl>`, `<time>`

- `<dl>`(description list)은 이름표 `<dt>`와 값 `<dd>`의 짝을 담는다. 스크린리더가 "현재 인구, 약 8,000~8,500명"처럼 짝으로 읽는다.
- `<time>`은 `dateTime` 속성이 있으면 그 값을, 없으면 **안의 글자 전체**를 시각으로 읽는다. 화면 글자에 "기준" 같은 말이 붙으면 `dateTime`에 시각만 따로 넣는다.

### flex의 방향과 `flex-1`

- `flex-1`은 부모의 **주축** 방향으로 남는 공간을 차지한다. 부모가 가로(`flex-row`)면 남는 폭, 세로(`flex-col`)면 남는 높이다.
- 부모 flex의 기본값 `align-items: stretch` 때문에 자식이 교차축으로 늘어날 수 있다. 가로 flex 안의 자식은 높이가 부모만큼 늘어나고, 그 자식이 세로 flex면 안쪽 `flex-1`이 그 늘어난 높이를 차지한다. 배치 방향을 바꿀 때는 남은 `flex-1`을 다시 본다.
