## 측정 계획
이력서에 숫자로 쓰려면 **개선하기 전 숫자를 먼저 재 두는 것**이 핵심이다. MVP 배포 날 잰 값이 "전", 개선 후 값이 "후".

| 무엇을 | 어떻게 재나 | 전 → 후 | 이력서 연결 |
| --- | --- | --- | --- |
| API 응답 크기 | Network 탭 (완료) | 도시데이터 174 kB → 인구데이터 2.4 kB | 필요한 데이터만 고른 API 설계 |
| 브라우저 요청 수 | 장소별 직접 호출 가정 vs BFF | 121번 → 1번 | 중복 요청 제거 |
| 하루 서울시 API 호출 수 | 사용자마다 호출 가정 vs 5분 캐시 | (측정) → 최대 34,848번 | 호출 한도 계산 과정 |
| 지도 데이터 크기 | 단순화 전후 `districts.json` 크기 (`pnpm build:map` 출력) | 87,235 B (11/2, 단순화 전) → (측정) | 변환 스크립트 |
| 첫 화면 성능 | Lighthouse Performance, LCP | (측정) | 성능 수치화 |
| 접근성 | Lighthouse Accessibility, 스크린리더로 구 25개 순회 | (측정) | WCAG 경험 |
| 드릴다운 애니메이션 | Performance 탭 프레임 드롭 | (측정) | 60fps 유지 여부 |
| React Compiler | 켜기 전후 렌더링 횟수·시간 | (측정) | 최신 React 최적화 경험 |
